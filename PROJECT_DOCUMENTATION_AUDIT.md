## Scope, evidence and counting rules

- Reviewed **420 physical locations**, including **209 in `_Organized Desktop`**. Current discovery covered all 98 top-level folders in scope and read 56,591 text documents; 0 filesystem read errors were recorded.
- Collapsed **85 duplicate/copy locations**. Excluded **37** reference-only, empty, generated or clearly trivial locations; reasons are retained in JSON.
- Counted coherent learning workspaces such as JS1, newcodexJS and newcodex3 once, while inspecting their nested applications. A frontend, API, worker or shared package is not an extra unrelated project. The Job Tracker folder contains three other independent products and a copied Job Tracker variant. The two independent products under z3 and the sample app embedded in Code Helper are also accounted for separately.
- The earlier “75 projects improved” report counted implementation targets. This audit uses application/workspace families, so its denominator deliberately differs from that historical batch count.
- Classification uses documentation content: onboarding, concrete architecture/flows, explanations and tradeoffs, hands-on progression, and engineering workflow. File names and word counts are discovery aids. Translations, repeated text and generated copies do not earn extra learning-depth credit.
- High/Exceptional means a substantial learning system is present. It does not certify every claim, setup command, historical line number, external PR review or exercise. Existing tests and apps were not run for this read-only audit. Source sizes include tests and styles and are approximate complexity signals.
- Copy groups are based on current source comparisons, with deterministic samples for larger locations, plus known relationships. Grouping means the same project family, not byte-identical complete trees. Different documentation at alternate locations is recorded per location.

## Review limits and reproducible evidence

[Machine-readable inventory](project-audit.json) contains every classified project, all alternate locations, exclusions, representative document paths and the next-batch recommendations. [Running location inventory](documentation-audit/location-inventory.json), [scan coverage](documentation-audit/scan-manifest.json), [representative readings](documentation-audit/representative-evidence.json), and [source comparison evidence](documentation-audit/duplicate-source-review.json) preserve the audit trail.

Representative local links were checked and results are retained with each evidence file. A missing historical source anchor or a stale root README should be rechecked before following that particular exercise. The presence of a curriculum is established separately from the correctness of every statement in it. Binary files and notebooks were inventoried separately; unrelated personal documents, fixtures and branding assets were not treated as software curricula.


## Concrete documentation-quality findings

- Representative review covered **1,868 documents**; none changed between discovery and the representative read. Full-text screening and representative reads are distinct from line-by-line technical verification.
- Of **8,016 simple local file targets** sampled, **862 did not resolve as written**. This includes copies and stale absolute paths; it is not a whole-repository broken-link rate. Parenthesized targets and line/heading anchors were not validated by this check.
- Saleor and Open edX contain useful source-specific exercises whose relative links can point from the wrong documentation directory. Their learning content qualifies, but navigation needs cleanup.
- Jellyfin’s Fable index links to multiple modules that are absent locally. Its existing cartography is useful; the promised full curriculum is not present, which is why it remains partial and is in the recommended next batch.
- MeterForge and CampusOps have meaningful specifications but mostly very short sprint outlines. FormForge also needs expanded walkthroughs. A fifteen-sprint label alone does not establish a finished course.
- VTCode has extensive developer reference; AI Helper includes a long proposed successor specification. Those were classified as partial rather than allowing reference/specification volume to imply a complete learning system.
- Historical PR reviews, performance claims and suggested resume stories were not independently verified. They are learning prompts, not evidence of your own work or of current production readiness.
