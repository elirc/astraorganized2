## Implement a safe checkout command lifecycle

CreateSession currently calls payment gateway before customer email/name and inventory validation, then decrements variant and coupon before Order.CreatePending validates input. A malformed customer can leave tracked mutations and a created intent; sold-out/inactive variants create an intent before rejection. Perform all deterministic validation (typed email/name, published/variant availability, coupon at one captured clock instant, money) before gateway or tracked mutations. Introduce small real domain preflight methods instead of copying rules into tests. Build complete pending order before applying reservation/redemption. Revalidate after external await as appropriate and document that this is not a distributed transaction or cross-context stock concurrency guarantee. Gateway/SaveChanges failure requires honest residual/compensation explanation; do not pretend in-memory EF tests prove SQL rollback.

CompleteOrder currently MarkPaid is domain-idempotent but service repeats save/email on every call; a later fake failed status attempts to fail an already-paid order. Define persisted terminal-state behavior early: repeat paid/failed completion returns the existing receipt without duplicate save/email/provider action; preserve first transition and positive receipt. Tests recording gateway/email/UoW call counts, invalid name/email/sold-out/inactive variant/expired coupon with zero external calls and unchanged tracked fields, valid stock/coupon once and repeated completion. Review domain failed-state retry policy. No real payments/email.

Important unchanged context: product mutation routes have no authentication and download only checks paid order ID, exposing license to an ID holder.
