## Confirmed defect and bounded change

`UpdateIssue` passes the live issue from `state.Issues` into `ApplyPatch`. That method assigns title/description/status/priority before validating later fields. For seeded `iss_atlas_101`, `{ "title": "Rejected replacement", "storyPoints": 101 }` returns validation failure but has already changed the singleton issue title. `GetBoard("ATLAS")` exposes it immediately. A later valid update to any issue serializes the whole state, making the rejected title durable without its intended audit. Locking serializes this error; it does not roll back assignments.

Apply the patch to an isolated candidate (the existing clone mechanism is suitable), validate completely, then replace/copy the accepted candidate into live state and append the audit/save exactly once. Preserve identity, project/sprint/reporter fields and omitted-versus-null behavior. No mutation of live issue, project timestamp or audit collection may happen on validation failure. Make malformed JSON field kinds in this PATCH path return the existing `VALIDATION_ERROR` rather than throwing from `GetString`/`TryGetInt32` after earlier assignments. Keep the repair centered on rejected PATCH isolation; no migration, project-membership system or production authentication is needed.

Disk-write failure atomicity, multi-process file coordination, assignee relationship policy, enum policy changes and creation rules are separate follow-ups. Do not claim this repair solves them.
