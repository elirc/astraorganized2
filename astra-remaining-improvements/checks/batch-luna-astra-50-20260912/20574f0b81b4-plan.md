## Concrete repair

Several list and mutation methods only filter workspace IDs and never require membership; workspace settings need an existing owner/maintainer policy, while inbox bootstrap exposes every member's notifications/preferences although its dedicated list filters to the current member. updateNotification must verify its recipient; planner mutations should verify ownership under an explicit existing-role policy. Validate tracker foreign keys before mutating state: project must belong to workspace, issue type to project/workspace, status to that issue type/workspace, labels and assignee to workspace. The original createIssue finds project globally and invents an ISS fallback; updateIssue Object.assign mutates before validating anything and may generate planner records. Preserve omitted PATCH fields, define null clearing where supported, reject unknown/empty/wrong-kind data at the service boundary. Derive member identity from the fixed demo user, validate document/workspace access, track ownership per socket, remove only that socket's presence on disconnect and broadcast the resulting list.
