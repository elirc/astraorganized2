## Concrete change

Make version-to-canonical PATCH mapping presence-aware. It currently returns all optional keys with undefined values, so Object.keys audit reports fields never supplied and fake Object.assign persistence may clear them even though Prisma skips undefined. Only include fields actually supplied, preserve false marketingOptIn, require valid nonempty canonical patches, and retain the intentional lossy v1 status/name mapping. Inspect schemas: do not promise independent nested-name omission if the public schema requires both parts. The adapters' union accesses are not narrowed by a separate version parameter; repair types with a proper discriminated contract/overloads or validated branch without blanket any casts. Runtime unknown version must fail rather than silently select v2.

At CustomerProfileService, enforce canonical runtime validation and derive CLIENT create owner from the session or reject a differing owner. The route currently supplies owner, but direct callers can currently create another owner's profile and raw repository data is writable. Keep existing repository read scope and profile mutation policy. Preserve supported lifecycle transitions and reject archived reactivation before persistence. Build changedFields from effective supplied changes, not a padded undefined map. If an empty/no-op patch is rejected or accepted, document and test the chosen contract.

ApiVersionService.updateRollout must validate known version and valid percentage/allowlist before repository writes: currently unknown versions can upsert operational config and write audit, then throw in applyRuntimeOverride. Reject invalid integer bounds/duplicates or normalize under a defined policy. Keep stable per-client rollout decisions and existing admin-only mutation. Make profile/version change plus audit use one transaction-capable operation if feasible; otherwise explicitly expose current storage failure limitation and do not claim atomicity from sequential awaits.
