# Astra source plan: OpenSource Upskilling Shop

Canonical `geminiorganized/OpenSource_Upskilling_Shop`. .NET/MediatR/EF shop with fake payments and React/Vite. Reviewed CheckoutHandler, RefundOrderHandler/validators, Order/OrderLine refund domain, controller and idempotency record.

Refund handler contacts provider before domain checks; duplicate lines fail ToDictionary, foreign IDs throw Single, over-refund/invalid state can occur after provider success. Domain Order.Refund mutates earlier lines before validating later lines and OrderLine.Refund accepts zero/negative. Add pure refund preflight returning validated plan/amount; reject empty/duplicate/foreign/unsafe quantities, invalid financial state and over-refund before provider or any mutation. Domain application must validate full batch before incrementing quantities/timestamps/timeline. Pre-resolve restock targets before provider if restock is required. Discounted orders currently refund gross UnitPrice, which may exceed paid Total: define deterministic net allocation/minor-unit remainder policy or explicitly reject unsupported discounted refund safely before provider and teach this limitation (do not silently overpay).

Idempotency records currently bind key/endpoint only; checkout replay can return another customer's order and changed refund payload silently replays. Store/compare request identity/fingerprint (cart/customer/email/discount for checkout; ordered normalized lines/restock for refunds) before replay, and use stable existing order only for matching requests. Preserve legacy record migration handling explicitly; no destructive reset. Checkout inventory reserve loop mutates earlier lines before discovering later stock failure; preflight all inventory and customer/order inputs before provider/reserve. Transaction and provider coordination are not atomic merely because SaveChanges runs once; document orphan-intent/commit failure/retry constraints.

Tests actual handlers with fake provider recording calls and EF test adapter; invalid refund leaves whole aggregate/provider call count unchanged, valid partial/full/replay one payment action, different key payload conflict, multi-line late-invalid preservation, checkout wrong replay identity. No real payments/email. Existing public checkout trusts CustomerId and cart IDs, so owner authentication remains a separate limitation unless properly connected to a trusted principal. Nine guides with refund ledger, preflight versus commit, idempotency comparison and complete matched exercises. Explicit runtime/DB test limits and guarded root apply.
