## Actual source and confirmed defects

The backend is Express 4, TypeScript, Prisma 5 and PostgreSQL. The frontend is a separate React 18/Vite package. There is no root npm workspace and neither package has a lockfile in the original copy. Read `backend/src/routes/taskRoutes.ts`, `controllers/taskController.ts`, `services/taskService.ts`, the Prisma schema, `index.ts` and both manifests. The README overstates implemented repositories, authorization and pagination: the service calls Prisma directly, task routes are unprotected, and lists are unpaginated.

POST/PATCH currently call Zod `.parse(req.body)` and discard the parsed result. The controller then forwards the raw body; `updateTask(id, data: any)` sends it directly into Prisma. Unknown fields stripped by the schema can therefore reach persistence anyway. The PATCH schema also omits legitimate task status, while the raw-body mistake accidentally lets it through. Both update and delete catch every Prisma error and return not-found, turning connection or programming failures into misleading 404 responses.

There are concrete setup gaps to resolve along with this task slice: `index.ts` imports a missing `projectRoutes.ts`; registration and portfolio creation omit the schema's required organization relationship; the backend placeholder test uses undefined test globals and has no runner dependency/script. Do not hide these defects with `any`, skipped type checks or mock-only compilation. Inspect the frontend's existing task status request before changing the wire shape.
