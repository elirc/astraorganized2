## Concrete repair

Focus on tenant-safe local mock-payment processing. `payments.routes.ts` currently requires only tenant context for the mock webhook, upserts a globally unique provider event before checking its payment, then updates payment by global ID and its invoice. An actor can name another tenant's payment. A duplicate provider event is replayed without checking its original organization/payload. The transaction includes payment/invoice/audit/outbox but not event creation, and concurrent duplicate deliveries can both process an event. GET events also exposes null-organization records to tenant users.

Move this workflow to a service with explicit tenant and permission checks, scoped payment/invoice lookup, strict normalized body, and a documented duplicate/conflict contract. Do not create an event for denied or nonexistent targets. Keep event claim, payment/invoice mutations, audit and outbox together in one Prisma transaction; choose a schema-supported conditional claim/serializable transaction with bounded retries if needed. Preserve the provider's globally unique event identity by rejecting cross-tenant/payload collisions, never returning another tenant's event. A succeeded payment must not be regressed by a later failed notification; decide and document the state transition contract based on existing domain transitions. Ensure failed events do not leave a paid invoice inconsistent. This is a local synthetic webhook, not a real payment provider integration.

Use typed client errors (403/404/409/400) and sanitized unexpected 500s instead of the existing message-based all-errors-as-400 response. Preserve compatibility with existing routes; inspect their error paths before changing the global handler. Do not add a real network integration or start the worker.
