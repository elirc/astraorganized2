# Astra source plan: jstrain3.0

Canonical `_Organized Desktop/04 JavaScript Training/jstrain3.0`. Express ESM/better-sqlite3 and React/Vite flags/experiments storefront. Reviewed cart/order routes, auth and DB initialization.

Cart POST accepts negative/fraction/string quantities; PATCH truthiness check also accepts noninteger/string. Reject non-safe-positive-integer quantities/product IDs and malformed/unknown bodies before SQL, validate accumulated quantity and stock policy. Preserve per-user row scope. Legacy invalid cart rows must be rejected again at checkout so negative quantities cannot increase stock or create negative totals. Checkout currently reads cart/stock outside transaction and performs unconditional decrement; move reads/validation into an immediate SQLite transaction and use stock>=quantity conditional update checked for one affected row. Order/items/stock/cart clear commit together. Tests real disposable SQLite: malformed quantities, hostile existing row, insufficient stock leaves all tables unchanged, own/foreign cart access, valid order and cart clear, rollback after injected persistence failure where feasible. Synchronous same-process route has no await gap; distinguish cross-connection transaction proof from ordinary sequential tests.

DB module hardcodes server/data/store.db. Add explicit test DB path/connection factory and import-safe Express app separate from listener/seed; never touch canonical database or run destructive seed. Read existing schema initializer before using temporary fixture. Money currently stored real dollar values; use careful integer-cent total calculation only if preserving schema/client contract and explain rounding, avoid destructive migration. No payment provider. Error middleware must map validation/conflict/malformedJSON predictably and keep unknown SQL detail out of responses.

Keep feature flag/experiment behavior as original unless tests reveal a necessary integration fix; no claim flags are authorization. Nine guides with cart/checkout transaction trace, sample quantities, rollback table, complete tests/exercises, snapshots and finite server tests/client build. Demo JWT fallback and experiment rollout storage remain explicit limits. Root guarded apply only.
