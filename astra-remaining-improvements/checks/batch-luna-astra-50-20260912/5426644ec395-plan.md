## Improvement

ReserveAsync calls equipment.Reserve before constructing the reservation, so invalid expiresAt leaves the live referenced equipment reserved. CheckoutService atomically checks out equipment before constructing Loan, so invalid dueOn leaves it checked out. Construct/validate the proposed reservation/loan and a single captured clock value before mutating equipment. Inject the existing IClock for deterministic service tests rather than mixing DateTimeOffset.UtcNow with expiry's injected clock. Loan.Return currently accepts a time before checkout; validate that before changing ReturnedAt.

Cancel/expire/return mutate one live entity then another; inspect transition preconditions for both before any mutation and serialize cooperating operations under a shared coordinator or storage-level operation. A ConcurrentDictionary does not make multi-record workflows atomic. Existing TryCheckOut locks only the equipment item, so preserve that safeguard and explicitly address or document borrower-limit races across distinct equipment. If adding a coordinator, it must be shared across scoped service instances and expiry worker, recover after failure/cancellation, and avoid leaking keyed semaphores indefinitely.

Do not claim clone-on-read or transaction rollback without implementing the corresponding store save contract: reservation/loan stores currently persist by reference and expose no Save method. Choose a bounded coherent design; at minimum all domain/time validation must precede mutations, and document remaining storage-failure atomicity rather than suggesting a lock protects disk writes. Avoid changing SQLite schema or claiming atomicity across a hybrid SQLite/in-memory deployment.
