## Confirmed repair scope

Separate public signup from privileged provisioning: public registration must assign a fixed least-privilege role and must not allow a direct service caller to restore privilege selection. If adding a privileged creation path, require the existing authenticated users:manage policy and test it. Otherwise keep admin bootstrap through explicit local seed instructions and accurately describe that boundary.

The final Express handler in `app.ts` has only three formal arguments `(error, req, res)`. Express does not recognize it as error middleware. Correct its four-argument shape and define safe JSON handling for AppError, malformed JSON, authentication-token errors and unexpected failures. Test actual HTTP errors through Supertest, not just the handler function. Unknown internal errors should not leak stack traces or database details. Retain useful local logging without logging credentials or tokens.

Inspect current JWT middleware before choosing precise handling. Preserve authentication and account-active checks. Review refresh-token subject versus stored user ownership and exact expiration boundary; add straightforward validation if absent. Do not present access-token revocation or rotation as implemented unless you implement and test it.
