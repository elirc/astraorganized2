## Concrete CRUD boundary defects

In `src/lib/socket/actions.ts`, board:join calls socket.join and touches presence before loadBoardSnapshot authorizes membership. If authorization fails, the socket can remain subscribed to a protected board. Authorize before joining or broadcasting; catch async errors and return a safe board:error without unhandled rejection. Heartbeat must require authorized room membership and cannot create presence for arbitrary IDs. Track joined boards accurately on leave/disconnect; handle attempted joins without corrupting a previous valid membership. Preserve positive member behavior and avoid treating the hardcoded demo user as production authentication.

The card:update handler always constructs `dueAt: null` when dueAt is omitted, so a title-only update clears an existing due date. Parse a precise runtime patch schema that distinguishes omitted, explicit null and valid date. Reject malformed dates/unknown or immutable fields before calling the service; serialize broadcasts consistently with the accepted patch. Apply validation to direct service callers where practical. Catch handler failures and acknowledge only accepted writes.

`moveCard` checks source board membership but does not validate that the target column belongs to the same board before mutation. Validate the destination (and any supplied neighbor) within the permitted board. Existing board-version checking compares expectedBoardVersion with card.version, and appendBoardEvent reads through global db inside a transaction; inspect these carefully before claiming concurrency correctness. Either repair with meaningful transactional tests or explicitly scope those as remaining limitations. A mocked query chain cannot prove PostgreSQL concurrency.
