# Luna implementation and review handoff

Use this checklist for the selected 50 projects. The user authorized all 24 remaining deliveries. Luna agents implement and independently review; Luna /root/review_w24 is the sole serialized canonical apply owner. Astra root orchestrates and runs validation. This current role assignment supersedes older root-apply wording.

- Read the actual source and the project's plan. Distinguish an existing safeguard from a new repair. A raw controller body does not imply raw ORM persistence if the original service already selects fields.
- Implement the planned behavior and required startup repairs, run focused unit checks, and finish the substantive course. Then send root a frozen executable-source handoff and proceed to the next assigned project. Root now owns final heavy builds and integrated validation, to avoid overlapping builds and free Luna for implementation. If a heavy build is already live, report its exact label/session/PID and do not duplicate it. Use run_project_check.py for unit/type checks; options precede ID/label. Root may return focused review repairs, which require a new source freeze before final checks.
- Test the actual entry point and persistence arguments. Verify mocks intercept the module the application consumes. Assert a nonempty positive result where an every/all check could otherwise pass on an empty list. Compare independent snapshots, not two references to the same mutated object.
- Reset mock implementations between independent tests when using persistent Vitest mocks; clearAllMocks clears call history only. Hook callbacks should return void (use braces) unless the test framework explicitly supports the returned value. Validate example inputs against the actual contract: a one-character reason cannot demonstrate a concurrency conflict when the schema requires three characters.
- Trace client callers when changing request or response contracts. Required backend fields must appear in client input types; empty 204 responses must not be parsed as JSON, direct auth responses may differ from CRUD envelopes, and backend rejections must not silently become successful mock results.
- Match evidence wording to its scope. A console assertion harness is not a collection of separately counted unit tests. Mocked persistence does not establish database durability/concurrency. A mutex does not automatically isolate readers or roll back mutations. A SQL rollback does not reset tracked EF objects.
- Create the nine prescribed astraupskill chapters with about 4,000 substantive words overall. Provide complete practice/solution pairs and concrete before/after requests. Include actual tested code copied from the implementation or test file, with imports and placement instructions. Label excerpts and unexecuted extensions. Do not invent a standalone fixture with missing aliases, undefined helpers or incorrect mock-hoisting order.
- Copy original source snapshots as exact bytes after checking the canonical file against the immutable baseline hash. Text read/write can silently change line endings. Use UTF-8 for new Markdown and inspect for corrupted punctuation.
- Link the course navigation, actual source, harness and local evidence. Historical command records may contain staging paths, but the learner's repeat commands must work from the delivered project folder.
- The spec uses summary as a list, changedFiles as a complete list of source/config/test/snapshot additions, checks as an object pointing to real evidence, and limits as a list. Do not include build output, private configuration, databases or dependencies. Root coordinates final portable verification; the designated Luna apply owner applies the reviewed manifest.
- Compare every baseline source/config file against the stage before handoff. Include even a small exported interface or build-generated source configuration change if the tested result depends on it; a manifest missing a changed source file does not reproduce the tested project.
- Hand off the exact terminal labels, live handles if any, source freeze state and unresolved limitations. Proceed only to the next project explicitly assigned to your lane. Never edit a delivered project again without a specific follow-up task.

- A tool response with session_id is still running, even if output is empty. Poll write_stdin until completion before interpreting output or directory contents. Never infer missing files from an unfinished command.
- For .NET, restore packages before testing. With missing TestSDK assets, dotnet test --no-restore can exit zero without executing any tests. Require nonempty test summary and actual TRX counters, not inferred counts from source annotations.
