# Astra source plan: OpenSource Upskilling Ramp

Canonical `geminiorganized/OpenSource_Upskilling_.Ramp`. ASP.NET expense app, mutable ConcurrentDictionary objects, bounded background queue and React frontend. Reviewed ExpenseService, ReceiptService, DataStore, BackgroundJobs/queue, DTOs, controller and state machine.

Repair failure-before-mutation boundaries in actual expense commands. Reject sets RejectionReason before validating Submitted->Rejected; invalid-state rejection leaves data changed. Update assigns fields before full service validation; controller annotations do not cover direct calls or undefined enum values. Normalize/validate entire candidate first (required trimmed fields, amount limits, defined category, currency length, date policy), evaluate policy on candidate then commit. Submit currently updates PolicyFlags before checking transition; guarantee rejected commands do not alter stored expense/history/timestamps/policy. Preserve role/report ownership rules.

StartReimbursement discards a ValueTask from bounded queue, marks Reimbursing before accepted work and cannot observe rejection/backpressure. Implement an explicit accepted-work/state boundary: either awaited async path with compensation and per-expense coordination or a synchronous TryEnqueue admission contract with transition held under the shared store lock. Controller must await if async. Worker must participate in coordination and guard duplicate completion; tests full queue/failing queue leaves Approved and history unchanged, valid enqueue produces exactly one Reimbursing event, retry no duplicate, worker transition once. Never block on async under lock. No actual payment rails; queue remains process-local/non-durable. CanSystemTransition currently allows any legal edge despite its name; restrict to system-only empty-role edges and test.

ConcurrentDictionary only protects dictionary operations, not multi-field entity mutation or list history; correct misleading DataStore comment claiming database swap is only persistence change. Avoid broad receipt-file rewrite; document existing replacement-file cleanup and upload/worker races if not repaired. Use synthetic fixtures/fake queue/clock or controllable job delay, no real receipts or accounts. Nine source-grounded guides, exact snapshots, failure ledgers and complete exercises, finite backend/frontend checks and explicit .NET runtime roll-forward if needed.
