## Preserve the working foundation

InMemoryBoardRepository already serializes updates under SemaphoreSlim and passes a clone to the callback. A callback exception does not replace stored state. Do not claim a failed domain move currently corrupts persisted repository state: the existing repository copy boundary protects it. Get and list return clones. Preserve these useful design decisions and teach them explicitly.

## Concrete improvements

The PATCH card route takes UpdateCardRequest with required title and ordinary nullable properties, and BoardService passes every property to Card.Update. Omitted fields are treated as replacement defaults, so a title-only PATCH loses description, assignment, due date and labels (and defaults priority). Implement deliberate presence-aware partial updates: omission preserves; explicit null clears only nullable fields; invalid required values and unknown enum values reject before mutation. Keep the existing UI's complete updates working. Reject an empty patch or document and test a deliberate no-op policy. Do not equate nullable with optional wire presence.

Direct aggregate operations also mutate before late validation. Board.MoveCard removes the source card and changes its position before finding/validating the destination; BoardColumn.AddCard inserts before checking capacity; Card.Update assigns fields before all label validation finishes. Validate proposed values, target existence, position and capacity before mutating, including same-column moves at capacity. Preserve source/target ordering, board version and timestamps on rejection. These direct-domain guarantees complement the repository's existing clone boundary.
