# ww50 independent early review — 2026-09-13

Decision: HOLD. The current `apiKeyRepository.updateConfiguration` and `rotate` use unconditional Prisma `update` selectors scoped only by `(id, organizationId)`. `apiKeyService` reads the key and checks `REVOKED` before entering its transaction, so a competing revoke can still be followed by a configuration update or rotation. The repository needs an ACTIVE plus expected-state/hash/version conditional write with a typed conflict result, and rotation history must use the actual predecessor from inside the transaction. `createApiKey` also counts active keys before its transaction, leaving the 25-key limit racy. Service inputs are still accepted as TypeScript shapes instead of parsing the existing Zod schemas. Existing tests cover only already-revoked service rejection and do not prove stale mutation, CAS conflict, omission/null roundtrip, one-time secret projection, or active-count concurrency.
