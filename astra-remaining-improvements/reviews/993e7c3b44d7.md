# GlobGame initial implementation review

Canonical: _Organized Desktop/12 Other Projects/GlobGame. Staged 30 files; original source has sixteen runtime files. No project or 12 Other Projects AGENTS.md was found. Existing parent instructions were checked previously.

The Next.js 16 application has a playable hierarchical merge engine and a Prisma/PostgreSQL puzzle schema, but no puzzle CRUD interface or mutation API. The daily resolver silently normalizes invalid filters, catches all database errors and logs raw error messages, then falls back to a sample for only 2026-02-18. Today therefore commonly shows no puzzle. The sample and seed duplicate data; seed replaces groups nontransactionally on each run. Payload recursion lacks graph validation, and the signed PRNG can produce a shuffle index outside the intended range. Local session hydration trusts nested tiles/history and swallows corrupt data; persistence runs after state adoption and suppresses failures.

Planned bounded improvement: a authenticated local-authoring puzzle CRUD vertical slice with strict mini-puzzle input, versioned transactions, publication immutability, safe seed/migration, public query validation and explicit demo mode. Improve session validation and visible save/recovery behavior. Add real database and browser failure checks and nine source-grounded mid-level CRUD learning documents. No existing database or personal environment files will be used.
