## What Astra did well
- **It found and removed live credentials, and described the remediation correctly.** The backup shows `scripts/populate-metaobjects.js` originally contained `accessToken: '[REDACTED-ROTATE-ME]'` inline for multiple stores. A `grep -rn "shpat_"` over the current `scripts/`, `test/`, `fixtures/`, `README.md` and `astraupskill/` returns nothing. Crucially, the course does *not* claim the problem is solved: "Removing those literals does not revoke the original credentials, remove repository history or sanitize backup copies. The account owner should revoke and replace them" (`VERIFICATION.md`). That is the correct security posture and the right thing to teach.
- **"Offline by default" is proven, not asserted.** `scripts/populate-metaobjects.js:8-18` documents that `plan` "sends no requests" and that "No command runs automatically on import or with no arguments", and `07-TRACE-LAB.md` explains the test that backs it: the CLI is launched in a child process with `fetch` replaced by a throwing function and still succeeds — "This demonstrates the absence of a network dependency more directly than calling the command a dry run while allowing hidden reads."
- **The uncertainty vocabulary is exactly right for integration work.** `scripts/lib/client.js:20` distinguishes read from mutation transport failure — `'Mutation transport failed; outcome is unknown. Re-export before retrying.'` vs `'Read transport failed or timed out.'` — and `:24` appends "mutation outcome must be reconciled" to non-OK HTTP. Reads retry (bounded, `Retry-After`-aware, `:22`); mutations never retry. The course's core claim ("a missing acknowledgement does not prove the remote action failed") is enforced in code.
- **The pagination tests are the best small lesson in the batch.** `test/migration.test.js` asserts that an opaque cursor is passed through GraphQL *variables* and never interpolated into the query string (`assert.ok(!calls[1].q.includes(cursor))` with a cursor containing `"` and `\`), that a non-advancing cursor is rejected, and that the page loop has a finite bound. That is three real-world bugs prevented in three lines.
- **Setup is genuinely reproducible** — the only project in B17 that gets this fully right: `package.json` declares `"engines": {"node": ">=22"}`, has zero dependencies, and ships `npm test`, `npm run check` and `npm run plan:example` with committed synthetic fixtures (`fixtures/source.json` has one `size_guide` definition; `fixtures/target.json` is empty). No account, no token, no Docker.

## Problems found (evidence required)
- **[D7]** The code is written in a compressed style that a junior cannot learn from. Multiple statements per line throughout: `scripts/populate-metaobjects.js:20` is `const command = argv[0] || 'help'; const options = {};`, and every one of the 42 tests is a single physical line, e.g. `test('changed existing entry is a conflict rather than a silent skip or overwrite', () => { const [s]=fixture(),t=structuredClone(s);t.store='target-learning';t.definitions[0].metaobjects[0].fields[0].value='Target edit';const p=buildPlan(s,t);assert.equal(p.conflicts.length,1);assert.equal(p.operations.length,0); });`. 105 lines of planner and 68 lines holding 42 tests is impressive density and poor teaching material — the course asks the learner to "inspect the planner" (`astraupskill/README.md`) but the planner is minified prose.
- **[D2]** Error hardening over-rotates into undebuggability. `scripts/lib/client.js:62`: `throw new Error('Shopify rejected the mutation with userErrors; inspect the plan and schema.')` — the `userErrors` array, which is the only thing that says *what* Shopify objected to, is discarded entirely. Same at `:30` for GraphQL `errors`. Not dumping credentials is right; dropping the error payload instead of redacting it leaves an operator with nothing. The course never raises this tradeoff.
- **[D4]** Off the main target. This is an external-API integration CLI: no HTTP server, no database, no SQL, no React/Next, no C#/.NET. The transferable content (idempotent create, conflict detection, cursor pagination, uncertain-outcome handling, plan/apply) is real and valuable, but a junior trying to become dependable at CRUD web development gets none of the routing, persistence or UI practice the rubric targets.
- **[D2]** Calling this an "improvement to the project" overstates it. Only one of the project's files was modified (`scripts/populate-metaobjects.js`); everything else is new. The rest of the repository — `shopify/assets/*` theme files, `.storybook/main.js`, `shopify/.shopify/metafields.json` — is untouched dead weight. `VERIFICATION.md` does admit "Existing theme assets and Storybook configs do not constitute a verified frontend build", but a learner cloning this repo sees a large Shopify theme they are told nothing about.
- **[D5 — security note, not a defect in the delivery]** The original token literal still exists at `AstraOrganized2/astra-remaining-improvements/backups/cf8875344b43/scripts/populate-metaobjects.js`. The limits mention "backup copies" generically; the follow-up owner should know there is a specific copy in the review workspace.

## One-paragraph summary for the index
A small, sharply-engineered lesson in integrating with someone else's API, wrapped around a genuine security find: the original script had live Shopify admin tokens pasted into it and ran a migration the instant you executed it. Astra rebuilt it as an offline-first `plan` / `export` / `apply` CLI where the plan is a reviewable artifact, conflicts are surfaced instead of overwritten, cursors are passed as GraphQL variables and validated for advancement, reads retry with a bound while mutations never retry because an unacknowledged write has an unknown outcome — and 42 zero-dependency tests, including a real loopback server, prove it without ever touching an account. It is also the easiest project in the batch to actually run (`npm test`, no account, no Docker, `engines` pinned). Two things keep it out of a learning path: the source and tests are written as compressed one-liners that are near-unreadable for a junior, and none of it is CRUD web development — no database, no routes, no UI. Read it for the uncertainty vocabulary and the pagination tests; do not try to learn JavaScript style from it, and note that the original tokens still need revoking by the account owner.
