## What Astra did well
- **The evidence file actively argues against inflating its own numbers.** `astraupskill/VERIFICATION.md`: "The **76 counted cases** are the 44 unit tests plus 19 library workflows plus 13 gameplay workflows. A workflow contains several related assertions. Repeated runs are not added together, and setup/audit/release/performance commands are additional evidence rather than extra counted cases." I checked all 44 unit-test names against the source: every one exists. This is the only deliverable in B17 that pre-empts the counting question, and it is right.
- **The bug fix is proved by a before/after measurement, not an assertion.** `evidence.json` `demolitionComparison` records `{variant: 'original', beforeWood: 1000, afterWood: 400}` vs `{variant: 'current', beforeWood: 1000, afterWood: 1000}` — with the *same* success message in both, which is exactly why the bug was invisible. `tests/demolition.test.ts:5-17` pins it: zero all resources, set wood to 1000, disable the warehouse, demolish a lumberyard, `expect(home.inventory).toEqual(before)`.
- **Optimistic concurrency is implemented and taught as a first-class idea.** `src/voyages.ts:6-18` puts `revision` on the record; every mutating call takes it (`repository.edit(id, revision, …)`, `.replace(…)`, `.delete(…)`, `.archive(…)` at `src/voyageLibrary.ts:46-48,83`); `VoyageError` carries a `code: 'conflict' | 'invalid' | 'missing' | 'storage'` (`src/voyages.ts:21-25`) that maps one-to-one onto 409/400/404/500. The course README then asks the learner to "Explain why the version check belongs inside the write transaction" and defines revision explicitly: "It is not a timestamp and it is not a count of game days."
- **Validation is real domain validation, not a type annotation.** `src/voyages.ts:31-35` NFC-normalizes and trims the title, rejects control characters, bounds title to 80 chars and notes to 2,000, and `snapshot()` measures size with `new TextEncoder().encode(raw).byteLength` — UTF-8 bytes, not `.length`. There is a test named for exactly that distinction ("bounds input and uses UTF-8 bytes rather than JavaScript character count").
- **The honesty extends to unflattering numbers.** `graphicsMeasurements` reports late-game `averageFps: 27.9` and the limits say plainly "the 101-building scene remains below 30 FPS in this run", with CPU/GPU named and "Results are machine-specific". The clean-install reconciliation hashes all 15 emitted assets and states `browserPackageMatchesCleanBuild: true` — so the browser evidence demonstrably came from the same bytes a fresh `npm ci && npm run build` produces.
- **The README is the best-written in the batch for a junior.** It states prerequisites ("You do not need experience with Three.js to begin. Leave the renderer alone for your first exercise"), defines record / snapshot / revision / transaction *before* the code, and closes with a concrete mid-level bar ("what happens if the user double-clicks, another tab updates the record, storage fills up… Do not answer these with 'the button is disabled'").

## Problems found (evidence required)
- **[D4]** There is no server, no HTTP layer, no SQL and no React/Next/.NET anywhere in this project. The CRUD lesson is excellent but lives entirely in a browser-local IndexedDB repository, so the learner practices none of the routing, request validation, server-side authorization or relational modeling the target stacks require. The course is upfront that "the domain remains a game", but a learner could finish it having never written an endpoint.
- **[D4/D7]** The UI layer teaches a pattern a React-bound junior should not copy. `src/voyageLibrary.ts:156` builds the whole dialog with `this.dialog.innerHTML = \`…${escape(this.message)}…\`` against a hand-rolled five-character escaper at `:3`. It is correct here, but "assemble HTML strings and rely on your own escape function" is exactly the habit React exists to remove, and no chapter flags it as a deliberately non-transferable choice.
- **[D6 — small but real]** One of the 44 counted unit tests is conditional: `tests/engine.test.ts:29` is `it.skipIf(!existsSync('artifacts/late-game-save.json'))('accepts the previously exported earned late-game fixture', …)`. The fixture is only regenerated when `TIDEBOUND_EXPORT_FIXTURE=1` (`tests/progression.test.ts:69`), so the suite silently reports 43 instead of 44 if `artifacts/` is absent, and can assert against a stale fixture if the engine changes without a regeneration run. `VERIFICATION.md` says "44 of 44 passed; four test files; process exit 0" without mentioning the conditional.
- **[D5]** Commands are PowerShell-shaped throughout (`npm ci`, `$env:TIDEBOUND_URL = …`), and the full evidence path is heavy: `evidence.json` `cleanSetup` records `npm ci` at 144.5 s and `npm run build` at 67.2 s, and the browser suites need a WebGL2-capable Chrome/Chromium plus `TIDEBOUND_BROWSER_PATH` or a Playwright browser install. A junior on a modest laptop should be warned that the browser workflows are an hour, not a coffee break.
- **[D7]** It is the largest course in the batch (7,815 words) attached to the largest codebase (1,387 lines of TS including a Three.js renderer and a 244-line simulation engine). The README mitigates this well by scoping the learner to `voyages.ts` / `voyageLibrary.ts`, but nothing states a realistic time budget for the seven chapters.
- **[D1 — minor]** The delivery summary's phrase "42 exact original text snapshots" is ambiguous; the underlying evidence key is `originalTextFilesPreserved: 42`, i.e. 42 pre-existing text files left unmodified, not 42 excerpts quoted in the course. The course itself does not repeat the ambiguous phrasing.

## One-paragraph summary for the index
Do not be put off by "it's a game" — the voyage library inside Tidebound is one of the cleanest small CRUD systems in this whole review set, and the course knows it: create, search, paginate, edit metadata, replace a snapshot, archive, restore, confirm-delete and export, all guarded by an expected-revision token so a second browser tab cannot silently overwrite the first, with typed error codes that map one-for-one onto 409/400/404/500. Astra also found a genuine accounting bug (demolishing a building while a paused warehouse left the island over capacity applied a negative refund and ate 600 wood of real inventory) and pinned it with a before/after measurement rather than a claim. The verification record is the most trustworthy in the batch: it runs a real Chrome, hashes the built assets to prove the browser evidence came from a clean install, reports its own sub-30-FPS late-game result, and explicitly refuses to inflate its 76-case count. The gap is stack: there is no server, no SQL and no React here, and the UI is `innerHTML` string assembly — so treat this as the course that teaches you what a repository boundary and a concurrency token are *for*, then immediately rebuild the same feature behind an HTTP API.
