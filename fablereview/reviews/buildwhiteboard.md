## What Astra did well
- This is the most on-target CRUD-web code in the batch, and the HTTP contract is correct in the details juniors usually miss. `server/index.js` sets `Location: /api/documents/<id>` and returns `201` on create vs `200` on open of an existing ID; `server/store.js` `checkVersion()` returns **400** for a missing/malformed version but **409** ("Document metadata changed. Refresh and retry.") for a stale one — two genuinely different client errors that most tutorials collapse into one.
- The acceptance ordering is implemented, commented, and tested. `store.js` `applyUpdate()` clones current state into a candidate `Y.Doc`, applies the incoming update *there*, checks the encoded size against `maxStateBytes` (413), and only then `this.persist(record); Y.applyUpdate(entry.doc, update);` — with the inline comment "Disk acceptance precedes live state mutation and broadcast by the server." The matching test is `'failed persistence prevents update broadcast and live server mutation'`, which asserts the server doc, the peer, and the saved bytes are all unchanged — not merely that an exception was thrown.
- `persist()` is a real atomic-replace: `writeFileSync(temporary, ..., { flag: 'wx' })` then `renameSync(temporary, destination)` in a `try`, with `finally { if (existsSync(temporary)) unlinkSync(temporary); }`. And there is a test that forces a *real* rename failure by putting a nonempty directory at the destination — `'real rename failure leaves disk record intact and cleans temporary file'` — rather than mocking `fs`.
- The course is candid about a bug Astra introduced and then fixed, with the mechanism explained. 03-WORKED-CHANGE: "standard providers forward received awareness updates. Rejecting every update mentioning another connection's client ID disconnected legitimate peers. The server now ignores older or already-known state before evaluating ownership of a genuinely new state." VERIFICATION repeats it. That is the kind of disclosure that makes the rest of the document believable.
- The course draws the line between the two consistency models sharply and repeatedly — metadata gets versioned optimistic concurrency, content gets a CRDT — and then names the trap: "a Live connection is not a receipt proving every local keystroke reached disk" (README), restated as Practice ticket 2 and again in the limits. This is exactly the distinction that makes someone dangerous-in-a-good-way in a code review.
- Every claimed limit is a real limit and is stated without hedging: "Origin checks are a browser access policy, not authentication"; "Docker scaffolding was not executed because the daemon was unavailable"; tombstones "retain lifecycle metadata" with no retention policy.

- **[D7]** `client/src/App.tsx` is 198 lines but several are enormous single-line JSX blocks. Line 194 is one ~900-character line containing the entire workspace `<section>`: editor panel header, character count, the `<textarea>` with six attributes, the preview panel, and the `<ReactMarkdown remarkPlugins={[remarkGfm]} rehypePlugins={[rehypeSanitize]} skipHtml>` element. Lines 190, 192, 193 and 195 are the same. A junior cannot diff, review or safely edit this; 01-CODEBASE-MAP describes the file's responsibilities but never warns about the formatting or suggests running a formatter first.
- **[D7]** The vocabulary load is high and partly undefined. 01-CODEBASE-MAP uses "state vectors", "sync step 1/step 2", "awareness", "relative positions" and "compaction" as if known; only "awareness ≈ temporary presence" is really explained. 4,419 words is thin for a course that has to cover HTTP CRUD *and* CRDT synchronization *and* an atomic-write persistence story. There is no diagram of the message flow (client → sync step 1 → step 2 → update → persist → broadcast) that the whole of 03-WORKED-CHANGE and 07-TRACE-LAB depends on.
- **[D5]** Setup requires four separate install steps across three lockfiles (`npm.cmd ci`, `npm.cmd ci --prefix client`, `npm.cmd ci --prefix server`, then `npx.cmd playwright install chromium`), two terminals, and the README notes that "The sample environment file is a reference; Node's entrypoint does not automatically load it" — so `.env.example` is a decoy for anyone who assumes dotenv. There is no `npm run install:all`-first instruction in the course README even though `package.json` defines that script.
- **[D5]** `docker-compose.yml`, `Dockerfile.client` and `Dockerfile.server` are present and unexecuted ("Docker scaffolding was not executed because the daemon was unavailable"). A junior who tries the Docker path first has no idea it is unverified until they reach the last paragraph of VERIFICATION.md.
- **[D2, minor]** Find-and-replace uses `text.split(search).join(replacement)` and `text.replace(search, () => replacement)` (`App.tsx:195`). The callback form is a deliberate and correct choice (it prevents `$&`/`$1` in the replacement string from being interpreted), and the course calls the behavior "literal search/replace" — but this subtlety is never explained, and it is exactly the kind of non-obvious line a learner will "simplify" back into a bug.

## One-paragraph summary for the index
This is the best CRUD-web project in the batch. The starting repo was broken — the server would not even boot, because a `require` call sat inside an ES-module package — and Astra rebuilt it into a proper Node service with a real HTTP metadata API: create-or-open returning 201 with a `Location` header or 200 for an existing ID, rename and delete guarded by an expected `version` that returns 409 when stale, 404 for a tombstoned ID that can never be recreated, and 400/413/415 for bad input, oversized bodies and wrong content types. The lesson built on top is the one worth learning: metadata and document content are two different consistency problems, so metadata gets optimistic locking and content gets a CRDT, and neither a connected socket nor a "Live" badge is a receipt that your keystroke reached disk. The persistence path writes a temp file and renames it *before* the live document is mutated or anything is broadcast, and there is a test that forces a real rename failure and proves the server, the peer and the bytes on disk all stayed unchanged. Two warnings: the React client is written in enormous single-line JSX that you should reformat before touching it, and the Yjs vocabulary (state vectors, sync steps, awareness) arrives faster than 4,400 words can explain — read the server first, the client second.
