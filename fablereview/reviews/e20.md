## Problems found (evidence required)
- **[D7]** This is a heavy course for a junior. `src/domain/erp-service.ts` is 2,602 lines, `src/domain/state-schema.ts` is 573, and the domain is double-barrelled: you must hold ERP semantics (quotation → sales order → invoice → payment, purchase receipt → stock ledger → GL) *and* the engineering lesson at once. The README's own checkpoint asks the learner to "identify the authorization check inside the transaction" in a 2,600-line service with no function index in `01-CODEBASE-MAP.md`.
- **[D7]** The suite is slow enough to break the feedback loop: `checks/erp-suite/unit-final.log` records `Duration 453.00s` for 39 tests, with single-line tests at 6-8 seconds each, run under `--maxWorkers=1 --no-file-parallelism`. A learner iterating on one change waits minutes. `04-TESTING-AND-DEBUGGING.md` should lead with the single-file/`-t` filter command.
- **[D4]** "SQLite" here is not relational modelling. `src/domain/database.ts` creates one table — `CREATE TABLE workspace (id INTEGER PRIMARY KEY CHECK(id=1), schema_version …, revision …, body TEXT NOT NULL) STRICT` — and stores the entire ERP state as a JSON `body`. You learn transaction semantics and rollback (genuinely), but you write no joins, no indexes, no foreign keys, and no migrations. The delivery states this ("a synchronous JSON aggregate in SQLite… not normalized or horizontally scaled"), and `05-PRACTICE` Assignment D asks the learner to move one collection toward relational storage — but as an exercise, not delivered code.
- **[D5, minor]** Setup writes a plaintext password to `data/local-credentials.json` and the README tells the learner to read it. It is gitignored and the file is generated per workspace, but the course never says "delete this when you are done", and a learner copying this pattern into a real project inherits it.

## One-paragraph summary for the index
The most complete on-stack application in the batch: TypeScript, Fastify, Zod, Vitest and real SQLite transactions, with eight master entities plus sales, purchasing, stock and accounting flows. The starter kept everything in memory (gone on restart), marked documents submitted before validation finished, treated a legitimate zero purchase rate as "missing" via `||`, de-duplicated identical ledger lines, and shipped a `start` script pointing at a path `tsc` never emits — all confirmed in the preserved backup and all fixed. The lesson worth the price of admission is the all-or-nothing submit: a receipt whose second line lacks a warehouse must leave no version bump, no audit event, no stock entry, and the test proves it by comparing the entire database row before and after. Two caveats: the SQLite table stores the whole workspace as one JSON blob, so you learn transactions but not relational modelling, and both the codebase (a 2,600-line service) and the test suite (453 seconds) are heavy for a first pass — come to it after a smaller Node/SQL course.
