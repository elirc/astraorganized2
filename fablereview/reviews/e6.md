## What Astra did well
- Four *different* classes of real defect, each verifiable in the backup. (a) No membership check at all: `backups/.../store.ts:54` `getWorkspace` looked up by id alone; now `this.requireMember(workspaceId)` runs first. (b) Cross-tenant read: bootstrap returned *every* notification and preference in the workspace; now filtered by `item.memberId === currentMemberId`. (c) Missing referential validation: `createIssue` accepted any `projectId`/`issueTypeId`/`statusId`/`assigneeMemberId`/`labelIds`; now each is resolved and scoped before the issue is pushed. (d) A presence leak: the old `disconnect` handler only deleted map keys whose `entries.size === 0` — i.e. it never removed the disconnecting socket's own entries, so stale presence accumulated forever and identity came from a client-supplied `memberId`.
- The status check is the kind of detail juniors miss: `store.ts:368` requires the new `statusId` to belong to *this issue's* `issueTypeId`, not merely to exist in the workspace.
- `StoreError` with a `statusCode` field turns domain failures into correct HTTP responses, and the fourth test proves it end-to-end through `app.inject` — 200 for a legitimate bootstrap, 403 for an unknown workspace, 404 with `"Issue not found"` for a missing issue — then closes the app in a `finally`, without binding a port (`apps/api/tests/boundaries.test.ts:96-110`).
- Pedagogy is the best in the batch. `05-PRACTICE.md` has nine escalating exercises *and* an "Acceptance criteria before implementation" section that pre-empts the exact mistake a junior makes: "A variable that points to the same issue object is not a before snapshot because `Object.assign` mutates that object." Exercise 7 is explicitly framed as exploration, not a delivered guarantee, and asks the learner to define the `clientMessageId` uniqueness contract before testing it.
- `VERIFICATION.md` distinguishes the full workspace build (run *before* the final API fixes) from the final API-only build and says so rather than implying one covered the other. It also explains why tests are invoked with a raw `tsx --test` command: "the original root package has no test script."

## Problems found (evidence required)
- **[D1]** `astraupskill/README.md` lists "preserves omitted PATCH fields" among the things the change *repairs*. It did not: `backups/.../store.ts:361` already used `Object.assign(issue, input, {updatedAt})`, which ignores omitted keys. `03-WORKED-CHANGE.md` gets this right ("The implementation deliberately supports omission"), so only the README overclaims.
- **[D2, cosmetic]** The `createMessage` rewrite left dead indentation: after removing the `if (channel) {` wrapper, `this.state.activities.unshift({` at `apps/api/src/data/store.ts:233` is still indented one level too deep. Lint passed, but it is a visible seam a reviewer would flag.
- **[D5]** There is still no `test` script anywhere (`package.json` and `apps/api/package.json` have `dev`/`build`/`typecheck` only). The course works around this with a long literal command instead of adding `"test": "tsx --test apps/api/tests/*.test.ts"`, so every learner must copy a 6-token command by hand and a CI run has nothing to call.
- **[D5]** The recorded test run took 189 s (`evidence/root-test-05.json`) mostly because `npm run build` must precede it to make `@workspace/domain` resolvable. `VERIFICATION.md` states the ordering but not the cost, so a junior will think it hung.
- **[D2/D1, unaddressed impact]** Scoping `getWorkspaceBootstrap().inbox.notifications` to the current member is a *contract change* for the Next web client, and no chapter checks whether `apps/web` renders workspace-wide notification counts. The final build recorded in `root-api-build-03` is API-only (VERIFICATION says so), so the frontend was not recompiled or re-reasoned after that change.
- **[D7]** The course assumes comfort with an npm-workspaces monorepo, Fastify plugin/`inject` testing, and Socket.IO acknowledgment callbacks with no introduction to any of them; `02-CONCEPTS.md` and `07-TRACE-LAB.md` are unbroken prose with no diagrams and no glossary.

## One-paragraph summary for the index
The best-taught course in the batch and a very good one to do second. It fixes four genuinely distinct bugs in a Fastify + Socket.IO workspace API — a store with no membership check at all, an inbox that leaked every member's notifications, issue creation that accepted foreign project/status/label ids, and a presence map that never released a disconnected socket while trusting a client-supplied member id — and it proves each with eight tests, including a real `app.inject` round trip that asserts 200/403/404. The practice chapter is the only one in the batch that tells you *how to know your test is valid* (snapshot with `structuredClone`, because `Object.assign` mutates the object you were about to compare against). It is a monorepo with no test script and a three-minute build-then-test cycle, so set up time before you start; budget a day across the three sessions the README lays out.
