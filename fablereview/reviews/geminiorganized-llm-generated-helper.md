## Does this transfer to the CRUD-web goal? (off-target-project note)

**The host project does not; the thing Astra built inside it does.** `LLM_Generated_Helper` is an LLM-plumbing Electron app — audio capture, STT, SSE streaming from providers, prompt assembly. None of that is CRUD web development. Astra's response was not to teach CRUD *through* the AI app, but to **write a second, unrelated application** in the same repo whose whole purpose is to be a CRUD teaching subject. That new app is genuinely on-target: real HTTP verbs and status codes, authentication, optimistic concurrency by revision, server-side pagination and search, referential integrity, state machines, and historical snapshots. The AI half contributes exactly one lesson — a good one — about publishing state only after a write is accepted.

Two caveats on transfer. First, the journal is hand-rolled plain JavaScript: `node:http` with a manual router, CommonJS, no TypeScript, no React, no framework, no SQL. That is excellent for understanding *what Express and Prisma are doing for you*, and poor as practice for the stack the learner is actually being hired on. Second, a learner must keep two unrelated applications straight in one repo; 01-CODEBASE-MAP handles this well ("identify the process you are debugging before setting a breakpoint") but it is still overhead.

## What Astra did well
- The Electron fix is a real data-loss bug, and the backup proves it. `backups/44013f102ff1/src/main/store.js` ends with `set(obj) { Object.assign(load(), obj); persist(); }` — the cache is mutated first, so a failed `renameSync` leaves memory and disk disagreeing and the user sees a "saved" value that does not exist. Worse, `decryptValue` caught the failure and returned `''` with the comment "treat as unset so the user is prompted to re-enter the key" — i.e. a machine-transfer or profile change silently wiped the stored API key. The replacement raises `failure(503, "A saved credential could not be decrypted... no key was cleared")`.
- The regression test for that bug asserts the right three things. `test/settings-safety.test.js:50-70` injects a `renameSync` failure, then asserts the throw, `store.get('resume') === 'Accepted resume'` (memory unchanged) **and** `fs.readFileSync(file)` deep-equals the pre-write bytes (disk unchanged), plus `readdirSync(directory) === ['settings.json']` (no orphan temp file). 03-WORKED-CHANGE explicitly argues why: "Merely checking that `renameSync` was called would not establish that the user still has a consistent accepted value."
- The new server's request envelope is unusually rigorous for a teaching app and every check is a teachable one: `boundary()` in `src/practice/server.js:26-47` rejects an unexpected `Host`, a URL over 2048 chars or starting `//`, a mismatched `Origin`, `sec-fetch-site: cross-site`, and any method outside GET/HEAD/POST/PATCH/DELETE (405); `body()` rejects non-identity `Content-Encoding` and anything that is not `application/json` (415). `src/shared/json-file.js` `jsonValue()` bounds nesting at 16 levels, rejects `__proto__`/`constructor`/`prototype` keys, and rejects non-well-formed Unicode via `value.isWellFormed()`.
- Zero runtime dependencies, and the README says so: "You do not need `npm install` for this learning app or its Node tests." On a machine where installs are the usual failure point, this is the most reproducible project in the batch.
- Verification is fully traceable. `astraupskill/verification-results.json` records `distinctChecks: 140, nodeTests: 120, browserChecks: 14, mockedRendererChecks: 6, baselineNodeTests: 73, regressionsFailedBefore: 8, regressionsPassedAfter: 8`, names all 14 browser workflows individually, and records the actual `node --test` argv and `exitCode: 0`. VERIFICATION refuses to inflate: "Repeated clean-copy runs are repeated verification of these tests, not additional distinct test cases" and labels the renderer harness as mocked.
- The limits section names things most courses would quietly skip: "Standard JSON parsing accepts duplicate property names using its normal last-value behavior; duplicate-key rejection was not added"; "this app never steals [a `.lock`] by age"; "Losing a token is not solved by rerunning setup: setup deliberately refuses to overwrite an existing workspace"; "The streaming provider parser and response-size behavior have not received a full production hardening pass."
- The pedagogy hits the exact distinctions juniors miss. README: "Score the answer zero initially if it needs work. Zero is a real score; leaving the field blank means no score" — then 05-PRACTICE Exercise 1's acceptance criterion is "you can distinguish a missing assessment from a low assessment", and 02-CONCEPTS asks the learner to predict the result for a missing field, `false`, zero, `null`, an unknown field and a stale revision. That is the `0` vs `null` vs `undefined` PATCH problem taught properly.

## One-paragraph summary for the index
This repo started as an Electron AI call assistant — audio capture, streaming providers, prompt assembly — which teaches nothing about CRUD, so Astra wrote a CRUD app inside it: a dependency-free local "Practice Journal" over profiles, questions, sessions and scored attempts, served from `node:http` with bearer auth, revision-based optimistic concurrency behind an exclusive writer lease, server-side search and pagination, lifecycle rules, referential integrity on delete, and immutable question snapshots so an edited question does not rewrite history. It is genuinely good material, and the strongest thing in it is small: zero is a real score and blank is no score, so the course makes you predict what happens for a missing field, `false`, `0`, `null`, an unknown field and a stale revision before you read the validator. The second lesson comes from the host app, where the original settings store mutated its in-memory cache before the write succeeded and silently erased any credential it could not decrypt — both now fixed, with a regression that asserts memory *and* disk are unchanged after an injected rename failure. Evidence is airtight: 120 Node tests, all present and countable on disk, plus 14 named browser workflows and 6 mocked renderer checks, with the 73-test baseline and the 8 first-failing regressions recorded. Two things to weigh: everything is hand-rolled plain JavaScript with no TypeScript, React, framework or SQL, so it teaches what a framework does for you rather than how to use one; and the delivery quietly repositioned the host project around the new app, retitling the README and demoting the Electron assistant to "legacy" in its own `package.json`.
