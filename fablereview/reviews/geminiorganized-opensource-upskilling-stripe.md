## What Astra did well
- `BillingStore.Write` (`src/Billing.Api/Infrastructure/BillingStore.cs`) is the single best teaching artifact in this batch: expired-receipt cleanup, receipt lookup with a **fingerprint** comparison (same key + different body → 409), the domain mutation, the audit row and the receipt insert all execute inside one `database.Transaction`. That is the correct answer to "how do I make a retry safe", written in 42 readable lines.
- HTTP semantics are right, not approximated. `IdempotencyMiddleware.cs:16-21` requires `If-Match`, returns **428 Precondition Required** when it is missing and 400 when the tag is malformed, and folds the `If-Match` value into the request fingerprint so a replay of a *different* version cannot be served from the receipt.
- Verification is the most thorough in the batch and every number is backed. `checks/stripe/full-01.log` ends with `Passed! - Failed: 0, Passed: 66 ... Total: 66`; `checks/stripe/browser-02/result.json` lists exactly the 15 workflow checks quoted in VERIFICATION.md with `"pageErrors": []` and `"serverStopped": true`; two reviewed screenshots at 1440×1050 and 390×844 are included.
- The original code was not destroyed. All 125 original text files, including every original `.cs`, are preserved under `docs/original/src/...txt` with a snapshot index, and VERIFICATION says plainly that the old docs "describe an earlier in-memory, unauthenticated implementation".
- The limits list is specific and falsifiable rather than boilerplate: "Limit: 5,000 domain records per workspace", "Operation receipts expire after 24 hours", "Provider callback signatures use a custom local HMAC protocol, not Stripe compatibility", "pending browser retry state is lost when the tab closes".
- `05-PRACTICE.md` exercise 3 is exactly the lesson juniors most need: add an archive filter, "apply it in SQL before pagination", "Explain why fetching one page and filtering it in React produces incorrect pagination", and test "a filter change while an earlier request is still in flight".

## Problems found (evidence required)
- **[D7]** The course is labelled junior-to-mid but the *implemented* surface assumes comfort with ETags/optimistic concurrency, idempotency fingerprints, transactional outbox, HMAC signing and multi-tenant authorization simultaneously. `02-CONCEPTS.md` covers "Money, tenancy, concurrency, receipts and time" in 825 words — roughly 165 words per hard topic. A junior will need the borrowbox/campusops-level material first.
- **[D7/D3]** Exercises 5–7 (credit-note/adjustment workflow, storage-model migration plan, real outbox sender with leases and a failure matrix) are senior design exercises with no reference solution — `06-SOLUTIONS-AND-REVIEW.md` is a review rubric, not answers. Good for a mid-level engineer, dead-end for a junior working alone.
- **[D2, minor]** `PaymentWorker.cs` and `WebhookDeliveryWorker.cs` are now 9-line classes whose only member is a `BatchSize` constant (consumed at `BillingEngine.cs:102,104`). The names promise background workers that no longer exist; the file comments explain the choice, but a learner grepping for the worker finds a constant holder. A `BillingLimits` class would be honest.
- **[D2, minor]** Batch processing reads with `db.All<PaymentJob>(w).Where(...).Take(...)` — load-everything-then-filter-in-memory, the pattern the course elsewhere teaches you to avoid. It is bounded by the disclosed 5,000-record cap and called out as Exercise 6, but it sits in the code a learner is told to imitate.
- **[D3, structural]** Because the app was rebuilt rather than repaired, the "worked change" (`03-WORKED-CHANGE.md`, safe customer editing) describes code Astra wrote from scratch, not a defect found in someone else's codebase. There is no red-first step and no diff to run against; the learner cannot reproduce the broken state except by reading `docs/original`.

## One-paragraph summary for the index
The most complete project in the batch and the right capstone for the .NET half of a CRUD path: a subscription-billing simulator with real SQLite persistence, workspace tenancy with three roles, full CRUD over seven related entities, SQL pagination and search, strong-ETag preconditions and a transactional idempotency receipt — and, unusually, a browser suite that actually ran, with 66 xUnit/HTTP tests and 15 named Playwright-style workflow checks whose evidence files match the claims line for line. Everything spot-checked against the source held, including the 428-on-missing-`If-Match` behavior and the single-transaction authorize/receipt/mutate/audit boundary in `BillingStore.Write`, which is worth reading on its own. The catch is level: this is a rebuild, so there is no broken code to repair and no red-first loop, and the last three exercises (credit notes, a storage migration plan, a real outbox sender) are senior design work with a rubric instead of answers. Do the smaller .NET courses first, then spend several sessions here; treat chapters 05–07 as a mid-level stretch, not a checklist.
