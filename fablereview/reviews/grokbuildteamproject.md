## What Astra did well
- Tenant scoping is enforced *twice*, in code and in the schema, and that is the course's central teaching point. `backend/prisma/schema.prisma:72` declares `assignee OrganizationMember? @relation(fields: [assigneeId, organizationId], references: [userId, organizationId], onDelete: Restrict)` and `:71` does the same for the parent project. 01-CODEBASE-MAP.md then asks the right question — "Explain why a plain foreign key to User would be insufficient" — rather than just showing the line.
- Identity is separated from authority properly. 01-CODEBASE-MAP.md: "Tokens identify the subject; they do not supply a trusted current team role"; `backend/src/middleware/tenantContext.ts` looks the membership up in PostgreSQL on every request and "A guessed organization header alone grants no access." This is the authz lesson most junior CRUD tutorials skip.
- Every mutation is a conditional update plus an audit insert in one transaction: `backend/src/repositories/projectRepository.ts:125-137` (`tx.project.updateMany({ where: { …, version: expected }, data: { …, version: { increment: 1 } } })` then `audit(tx, …, expected + 1)`), and `:236-249` the same for tasks after `verifyAssignee(tx, context.organizationId, data.assigneeId)`. The delete path re-reads and throws `conflict()` when the version moved (`:157`, `:271`).
- Astra names the original code's weakness honestly and it is verifiable. README: "route tests accepted several incompatible statuses as success" — the backup's `backend/src/__tests__/taskRoutes.integration.test.ts:60` really does read `expect([201, 400, 401]).toContain(res.status);`, and `:40` `expect([200, 401]).toContain(res.status); // depending on middleware`. The backup's `routes/taskRoutes.ts` has no auth middleware at all.
- Test counts are exact, not rounded. 46 + 12 + 6 + 3 + 16 = 83, matching both VERIFICATION.md and `deliveries/4c93b4cf7530.json`.

## Problems found (evidence required)
- **[D7]** The course tries to teach tenancy, membership-derived authority, compound foreign keys, optimistic versioning, transactional audits, draft preservation and navigation guards in 4,571 words. 02-CONCEPTS.md carries the load in 541 words, which is roughly one paragraph per large idea. A junior arriving from "React + fetch" will need a second pass or outside reading; there are no time estimates or prerequisite list in `astraupskill/README.md`.
- **[D3, minor]** `backend/src/repositories/taskRepository.ts` is a 9-line re-export of `projectRepository.ts`, and `backend/src/services/taskService.ts` is 9 lines for the same reason. 01-CODEBASE-MAP.md:17 does explain it ("The original task service and repository entry files now expose the scoped operations"), but 03-WORKED-CHANGE.md then says "The repository finds the task with its task ID, project ID, and selected organization ID" without naming which file, so a learner following the worked change opens the shim and finds nothing.
- **[D5, minor]** VERIFICATION.md says "Docker Compose configuration is supplied, but verification used installed PostgreSQL executables rather than a Docker daemon" — honest, but it means the one setup path a junior on a fresh machine is most likely to reach for (`docker compose up`) is the untested one. `docker-compose.yml` was modified by the change and never exercised.

## One-paragraph summary for the index
The best multi-tenant CRUD course in this batch, and the one worth doing right after the order/inventory project. It starts from a scaffold whose task routes had no authentication and whose tests asserted `expect([201, 400, 401]).toContain(res.status)`, and ends with a workspace where a request's authority comes from a database membership lookup rather than its token, where every project, task and comment query is scoped by `(id, organizationId)`, where compound foreign keys make the database reject a cross-team assignee even if the service is bypassed, and where every mutation is a version-guarded `updateMany` plus an audit row in one transaction. 83 checks (58 backend, 6 component, 3 setup, 16 Chromium) exist on disk in exactly the claimed proportions, and the limits section is candid about what is not there — no invitations, no membership UI, no idempotency receipts, no tested Docker path. Expect it to be dense: 4,571 words is not much for tenancy, optimistic concurrency, transactional audit and draft recovery, so plan two passes.
