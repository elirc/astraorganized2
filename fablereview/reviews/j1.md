## What Astra did well
- Both defects the course names are real. `backups/9b2478e93c69/src/todo/model/Task.java:9,11` has non-final `completed` / `completedAt` with a mutating `markCompleted()` at :51; `backups/.../src/todo/App.java:46-48` calls `saveTasksToDisk()` only in the `finally` of the main loop — so a crash or kill lost everything. The new `src/todo/model/Task.java` is `final` with all-final fields, `edit()`/`withCompletion()` returning new versions, and `TaskManager` saves per command.
- The verification harness is the best in the batch. `scripts/verify.py` compiles with `--release 17`, runs the Java suite in an OS temp dir, drives the real CLI through stdin for eight scenarios, and then **forks two independent JVMs**, gates them on a shared `go` file, and asserts `combined.count('ACCEPTED')==1 and combined.count('CONFLICT')==1`. That is a genuine cross-process concurrency proof, not a mock.
- Failure paths are tested where they matter: `TaskWorkflowTest.java:64` subclasses `TaskRepository` to throw from `replaceAtomically` and then asserts both the on-disk bytes and the in-memory list are unchanged; `:66` asserts that a *different* pre-existing `.legacy-backup` blocks conversion rather than clobbering it.
- The course consistently bridges to the target stack rather than pretending the CLI is a web app: 02-CONCEPTS.md maps immutability to "read DTOs and explicit commands", and README says the version check maps to a future `If-Match` "but that is a design exercise until implemented and tested".

## One-paragraph summary for the index
A small Java CLI that is a surprisingly good vehicle for the two ideas juniors most often get wrong: optimistic concurrency and durable writes. The starter mutated task objects in place and only wrote to disk in a `finally` block on exit; the rewrite makes `Task` immutable with a version, persists a validated snapshot before publishing anything to memory, and refuses to replace an unreadable file with an empty list. Evidence is unusually strong — 35 unit tests plus eight scripted CLI runs, including two real JVMs racing for the same file where exactly one wins. The catch is that it is Java: there is no HTTP, no SQL and no auth, so read it for the reasoning and do the C#/Node port yourself before calling it stack practice.
