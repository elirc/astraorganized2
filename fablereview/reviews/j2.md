## What Astra did well
- The core teaching problem is genuinely present in the original and genuinely fixed. `backups/1a8f0f6b63c8/src/librarytracker/storage/FileStorage.java:34-38` is `save()` → `saveBooks(books); saveBorrowers(borrowers);` — two separate writes with no atomicity, so a failure between them leaves a half-updated library. 02-CONCEPTS.md opens exactly there: "Explain why independently saving books and borrowers can produce an inconsistent workspace, even when both individual files contain valid text."
- The historical-snapshot lesson is modelled in code, not just described. `src/librarytracker/model/Loan.java` is a `record` carrying `bookTitle` and `borrowerName` validated at construction, so renaming a borrower cannot rewrite a past receipt — and the course states the acceptance sentence for it in README ("Renaming a borrower changes the current profile but not the name recorded on a previous loan").
- The original parser was permissive in the way juniors most often write: `record.getOrDefault("checkedOut","false")` through `Boolean.parseBoolean` silently turns any garbage into `false`. The new `FileStorage` is strict and bounded (`MAX_BYTES = 10 * 1024 * 1024` at :17, enforced at :38, :44, :225, :230).
- Unlike J1, the Java source here was actually formatted (google-java-format 1.28.0, SHA-256 verified per VERIFICATION.md) and **recompiled after formatting** — `checks/library-tracker/results.json` carries `"compiledAfterFormatting": true`. The test file is readable multi-line Java.
- Legacy migration is non-destructive and tested: VERIFICATION claims "The conversion test compares both original files before and after an accepted mutation and confirms that neither was modified", and the limits section admits what cannot be recovered ("Earlier returns already discarded by the old format cannot be reconstructed").

## Problems found (evidence required)
- **[D4]** Off the target stacks. Java CLI, no HTTP, no browser, no SQL, no auth — stated in the delivery limits ("The project remains a Java CLI without HTTP/browser UI, authentication, ownership policy, external notifications, fines, renewals or SQL deployment"). The web and SQL work is design-only in `05-PRACTICE.md`.
- **[D8]** Shares a framing template with J1 and j3. `05-PRACTICE.md` opens "Use a separate branch or copy and fictional data. Write acceptance criteria before coding…" where J1 opens "These exercises build on the existing guarantees… Work in a separate branch or copy and use fictional task files." Both README files end with the same three-artefact ask ("one successful X, one rejected stale X, and one failed storage write"). The domain content differs; the scaffolding does not.
- **[D7, minor]** The CLI is menu-number driven with 18+ options and the course never prints the menu. The verification script's scenario strings are the only place the numbering appears (`scripts/verify.py:22` `'10\n0\nEdited book\n…\n12\n0\n…\n17\n0\nYES\n18\n0\nYES\n14\nEdited\narchived\n9\n'`), which is not a readable reference for a learner following 07-TRACE-LAB by hand.
- **[D5, minor]** IDs start at zero "because existing legacy files may already use that convention" (course README), but `Loan.java` validates `Values.identity(id, 1)` — i.e. loan ids are 1-based while book/borrower ids can be 0-based. That inconsistency is never explained and will confuse a learner writing their own test fixtures.

## One-paragraph summary for the index
The best "one business action, several records" lesson in the batch. The starter saved books and borrowers to two separate files with no coordination and parsed them permissively, so a failure mid-save left an inconsistent library and a bad byte silently became `false`. Astra collapsed the pair into one strict, bounded, atomically replaced snapshot guarded by a cooperative lock and a baseline comparison, and added the record the design was missing: an immutable loan receipt that freezes the title and borrower name accepted at checkout, so later renames do not rewrite history. 44 unit tests and nine scripted CLI runs (including two racing JVMs) back it, and the source was formatted and recompiled so it is pleasant to read. It is Java, so treat it as concept practice: the HTTP and SQL versions are exercises, not code.
