## What Astra did well
- The code change is genuinely substantive, not cosmetic. `src/quiz/QuestionBank.java:55-72` implements the whole durable-write protocol in one readable `commit()`: `tryLock()` on a sidecar `.lock`, `Arrays.equals(original, Files.readAllBytes(file))` stale check, write-temp-then-`ATOMIC_MOVE`, and only then `questions = List.copyOf(candidate)` — i.e. memory is published *after* durability, which is exactly the lesson the README sells.
- Tests exercise observable behavior, not call counts. e.g. `"outside file edits are preserved"` writes junk to the file behind the bank's back and asserts the bank refuses the delete *and* the junk survives; `"two loaded editors reject stale second save"` builds two `QuestionBank` instances on one file and asserts one winner.
- Verification is unusually honest. `VERIFICATION.md:11` states the limits plainly: no HTTP/DB/browser, advisory locks can be ignored by non-cooperating editors, "No power-loss durability claim is made", and "Startup reports errors in text but does not currently return a distinct failure exit status."
- The practice ladder (`05-PRACTICE.md` §4–6) is the bridge to the target stacks: real HTTP status mapping (201/204/400/404/409), teacher-vs-learner response models ("A route must not dump every field from Question merely because it is convenient"), and a SQL version-column exercise that explicitly critiques the file-level conflict policy just built.

## Problems found (evidence required)
- **[D4]** The whole project is Java. The learner's target stacks are JS/TS/React/Node/Next and C#/.NET; nothing here is written in either. The transferable content (optimistic concurrency, atomic replace, validation at the domain boundary) is real, but a junior must do the translation unaided — §4/§5 of `05-PRACTICE.md` say "a Java HTTP framework of your choice" and "Design Question and Choice tables" with no starter, no schema, no TypeScript/C# analogue.
- **[D5]** The runner is Windows-PowerShell only (`run.ps1`) and resolves `javac` from PATH with no `JAVA_HOME` fallback (contrast `j5`/`j7`, whose runners do check `$env:JAVA_HOME`). A junior on macOS/Linux, or with a JDK installed but not on PATH, gets no documented path forward; `04-TESTING-AND-DEBUGGING.md:3` just says "Run `./run.ps1 -Test` with JDK 17 on PATH."
- **[D3]** Predictions are asked for in prose but there is no prediction-vs-actual table or answer key to check against. `07-TRACE-LAB.md` says "Expect a 'Not saved' conflict" and "Record planned, answered, correct, incorrect and unanswered counts in a table", but no expected table is supplied anywhere, so a junior cannot self-grade the trace lab.
- **[D7]** `02-CONCEPTS.md`/`07-TRACE-LAB.md` use "snapshot", "candidate state", "advisory/cooperating lock", "publication" without a glossary. They are used consistently and mostly explained in context, but a junior meeting "cooperating-writer protocol" for the first time has nowhere to look it up.

## One-paragraph summary for the index
This is one of the best-executed courses in the batch, and it is about the right *ideas* on the wrong *stack*. Astra rebuilt a toy Java quiz CLI into a small but real durable-CRUD engine — unique identity, validated replacement, an advisory lock, an optimistic stale-bytes check and atomic file replacement — and backed it with 28 behavioral tests that genuinely fail if you remove the guarantees. The writing is specific to this code (menu numbers, method names and line behavior all check out), and `VERIFICATION.md` states its limits honestly instead of overclaiming. The catch for a JS/TS or .NET junior is that everything is in Java and the web/SQL translation is left entirely as prose exercises. Do this one as an elective *after* you have a Node or ASP.NET CRUD app of your own, and read it for the concurrency-and-durability reasoning rather than for code you will reuse.
