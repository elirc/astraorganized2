## What Astra did well
- The root-cause story is the best in the batch and it is concrete: "It constructed an order with a discount but no items, recalculated against a zero subtotal, and clamped the discount to zero. Adding restored items afterward could not recover the original value" (`astraupskill/README.md`). That is an order-of-construction bug — exactly the class of bug that bites juniors wiring EF Core / Prisma aggregate loads, and it is explained without hand-waving.
- The invariants are enforced where they belong, not in the UI. `src/oms/domain/Order.java:120-123`: `if (!isEditable()) throw …("Orders in " + status + " status cannot be edited.")` with `isEditable() { return status == DRAFT || status == SUBMITTED; }`, and `OrderService.java:90` refuses `PAID`/`SHIPPED` for an order with no items. A junior can delete the CLI and the rules still hold — the course makes that point explicitly.
- Single-snapshot persistence (`FileDataStore.java:22`, `oms.snapshot.txt`) replacing four independent writes is a genuinely useful lesson about partial-write inconsistency across related entities, with a footer count check and a stated non-claim ("It is not a cryptographic integrity mechanism", `VERIFICATION.md`).
- `VERIFICATION.md` is the most scrupulous document in this batch. It names the seven tests that failed against the *original* code, distinguishes automated from source-reviewed coverage ("Failed normal exit retains the session for retry; that branch was source-reviewed, while automated failure injection exercised storage replacement itself"), and explicitly warns "Paid cancellation remains a local status transition, and should not be presented as a completed refund workflow."

## Problems found (evidence required)
- **[D4]** Off-stack. This is Java, and the target stacks appear only as destinations. Ironically it is the *most* transferable of the three Java projects (aggregate boundaries, status machines, price snapshots on line items are straight out of any .NET/EF Core or Prisma order model), which makes the absence of any C#/TS rendering of the same model the biggest missed opportunity in the deliverable.
- **[D5]** `astraupskill/README.md` tells the learner to run `run.ps1 -DataPath .\data\learning-orders` and says "With no override, the runner uses the project's `data` directory" — **no `data/` directory exists** in the project. The store creates it on first save, so nothing breaks, but there is no seeded catalog/customer fixture, which means the "Create a customer and an active product priced at 10.00 … subtotal should be 20.00, discount 5.00, and total 15.00" walkthrough requires ~8 minutes of manual menu data entry before the first interesting observation.
- **[D5]** PowerShell-only (`run.ps1`); no macOS/Linux invocation documented anywhere in the 9 files.
- **[D3]** The trace lab and README state expected values inline ("the total becomes 25.00") but there is no separated predict-then-reveal structure — the answer is in the same sentence as the prompt, so a learner reading linearly never actually predicts. Compare `05-PRACTICE.md`, which does keep acceptance examples away from `06-SOLUTIONS-AND-REVIEW.md` properly.
- **[D7]** The course uses "aggregate", "detached", "snapshot", "restoration vs. replaying interactive edits" as load-bearing vocabulary. `02-CONCEPTS.md` explains them in context but there is no glossary, and "aggregate" is DDD vocabulary a junior will not have met.
- **[D1 — minor]** `VERIFICATION.md` cites "The central implementation report and project manifest `14690be423dc`" — a path outside the project, unresolvable by a learner reading in place.

## One-paragraph summary for the index
The richest domain model of the three Java experiments, and the one whose ideas map most directly onto a real .NET or Node CRUD job. Astra found a subtle aggregate-restoration bug — the order was rebuilt discount-before-items, so every saved discount silently became zero on reload — fixed it by restoring the whole aggregate at once, then went further: reads return detached copies, PAID orders refuse line edits, sub-cent money is rejected rather than rounded, and four separate entity files collapse into one atomic versioned snapshot so related records cannot be half-written. 35 behavioral tests back it and `VERIFICATION.md` is candid about what was only source-reviewed. The blocker for this learning path is stack: it is Java, there is no C#/TS rendering of the same model, and the promised `data/` fixture directory does not exist, so you hand-enter the walkthrough data. Take it as an elective for aggregate-and-invariant thinking, and plan to re-implement the order model in EF Core or Prisma immediately afterward.
