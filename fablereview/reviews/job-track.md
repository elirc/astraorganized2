## What Astra did well
- This is the most useful CRUD change in the batch, and it targets a bug juniors write constantly. `server/src/validation.js` changed every optional field from `.or(z.literal("").transform(() => undefined))` to `... => null`, and the PUT handler then distinguishes the three states explicitly: `notes: data.notes !== undefined ? data.notes || null : existing.notes` (`server/src/routes/applications.js:163`). Omitted keeps, blank clears, present sets — the exact distinction most partial-update handlers get wrong.
- The salary fix is not cosmetic. Before, `z.coerce.number()` on `""` yields `0`; after, `z.preprocess((v) => (v === "" || v === null ? null : v), z.coerce.number().int().nonnegative().nullable().optional())` keeps a blank salary null. A junior who has ever shipped a `$0 minimum salary` row will recognise this immediately.
- Idempotent status transition done properly: `server/src/routes/applications.js:228` returns `res.json({ item: existing })` when `existing.status === nextStatus`, *before* consulting `ALLOWED_TRANSITIONS`, so a retry does not become an invalid-transition 400 and does not bump `updated_at`.
- The Zustand fix is a real framework bug, not busywork: `client/src/components/ProtectedRoute.jsx` went from `useAuthStore((state) => ({ token: state.token, isReady: state.isReady }))` — a fresh object every render, which loops under Zustand v5's `useSyncExternalStore` equality check — to two scalar selectors. Same fix applied in `LoginPage.jsx` and `RegisterPage.jsx`.
- The tests assert the things that matter, including authorization: `test/applications.test.js:89` registers a *second* user, swaps the bearer token, and asserts `PUT /applications/:id` returns 404 for a record it does not own, then restores the original token. It also asserts `updated_at` is unchanged after a repeated transition rather than just checking the HTTP code.
- Test isolation is genuine: `mkdtemp` + `JOB_TRACK_DATA_DIR` + synthetic `JWT_SECRET` set before `require("../server/src/server")`, `app.listen(0)`, then `rm(directory, {recursive:true})` — no risk to the developer's real data directory.

## One-paragraph summary for the index
This is the course to do first in this batch. It is a small Express + SQLite + JWT API with a React/Zustand client — exactly the target stack — and the change fixes the bug every junior ships at least once: a partial update where a blank form field silently keeps the old value, or a blank salary becomes zero. You will see how Zod's `.transform()` decides between "omitted", "cleared" and "changed", why a status transition should be idempotent and leave `updated_at` alone, why a list needs an `id` tie-breaker, and why a Zustand object-selector causes an infinite render loop. The three tests run the real API over HTTP against a throwaway database and include a genuine cross-user ownership check. The prose has the same template padding as the rest of the batch, and you should pin Node 22.16 before `npm install` because `better-sqlite3` is a native module.
