## What Astra did well
- **The change is the real thing.** The old handler ran the subtree check with `query(...)` and then a *separate* `pool.query("UPDATE ...")` (`backups/28/server/src/index.ts:117-135`) — two connections, no transaction, a textbook time-of-check/time-of-use gap. The new one acquires a client, `BEGIN`s, locks, re-checks under the lock, updates and `COMMIT`s, with `ROLLBACK` in `catch` and `client.release()` in `finally` (`server/src/index.ts:117-141`). The lock/release discipline is correct.
- **The test actually races.** `test/feature.test.ts:13-18` fires `Promise.all([move A under B, move B under A])` and asserts `results.map(x => x.status).sort()` deep-equals `[200, 400]` — exactly one winner — then asserts `aa.depth + bb.depth === 1` and that `GET /api/tree` still returns 200, i.e. the tree is still readable and acyclic. A concurrency test that asserts a *deterministic* outcome rather than "no crash" is rare and hard to write.
- **The tradeoff is taught, not hidden.** `02-CONCEPTS.md:9`: "The lock is deliberately broad: it serializes structural writers for this small teaching app. It is easy to explain and inspect, but reduces concurrent write throughput. A more scalable design requires a proven locking or serializable-retry strategy, not simply removing the lock." It also notes the policy "cannot prevent arbitrary direct SQL from creating a cycle". That is honest engineering writing.
- **`asyncRoute` is a real bug fix, not decoration.** Express 4 does not catch rejected promises from async handlers; before this change a DB error in `GET /api/tree` would hang the request. Every route was wrapped.
- **The test harness is excellent and is the reproducibility story.** `test/database.ts` refuses any database whose name does not start `astra_test_`, creates a per-run schema named from a UUID, strips `DROP`/`CREATE EXTENSION` statements out of the teaching `schema.sql`, points `DATABASE_URL` at that schema via a `search_path` option *before* importing the app's pool, binds the real server to an ephemeral loopback port, and drops the schema on close. `VERIFICATION.md` explains all of this and warns that an interrupted run can leave a schema behind.
- `VERIFICATION.md` "Reproduce" gives exact PowerShell, explains why it bypasses the `db:setup` script's POSIX `$DATABASE_URL` expansion, and notes the pgcrypto requirement. This is the only setup section in the batch a junior could genuinely follow on a fresh machine.

Two similar "not found" conditions get different status codes in the same handler; the course does not justify the asymmetry, and `test/feature.test.ts:22` bakes the 400 in.
- **[D2, minor]** The `SHARE ROW EXCLUSIVE` table lock serializes every structural write globally. That is defensible for a teaching app and is disclosed, but nothing bounds the wait — there is no `lock_timeout` or `statement_timeout`, so a stuck transaction blocks all moves indefinitely.
- **[D5]** `package.json` still declares every dependency as `"latest"` with no lockfile (pre-existing), which `VERIFICATION.md` acknowledges but the README setup block does not.

## One-paragraph summary for the index
The strongest course in this batch and the one worth clearing a weekend for. It takes a real bug — an org-chart "move node" endpoint that checked for a cycle and then updated in two separate queries, so two concurrent moves could each pass their check and together create a cycle — and fixes it properly with a transaction, an explicit table lock, and a re-check performed under that lock. The concurrency test genuinely races two opposing moves and asserts that exactly one returns 200 and one returns 400, and the test harness spins up a disposable PostgreSQL schema per run and refuses to touch any database not named `astra_test_*`. The concepts chapter is the only one in the batch that argues a tradeoff honestly, including why the broad lock is the wrong answer at scale. It is also the hardest project here: do `course-roster` first, and expect to spend time on recursive CTEs. The generic practice and solutions chapters are the only weak part.
