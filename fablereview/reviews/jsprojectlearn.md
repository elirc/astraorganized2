## What Astra did well
- The conflict boundary is genuinely implemented and the course describes it precisely. `src/game/storage.ts:8-42`: `navigator.locks.request(STORAGE_KEY, work)` wraps the write; inside, `proposal.revision !== current.revision` throws **before** `storage.setItem`, so a rejected save cannot have partially written. There is even an exhaustion guard at `:35` (`current.revision === Number.MAX_SAFE_INTEGER` -> "Save revision is exhausted. Export for recovery.").
- Domain operations are pure and immutable, which is exactly the habit a React/TS junior needs. `src/game/notes.ts` `updateNote` builds a new collection with `progress.notes.map(...)`, rejects an unknown id with a message that tells the user what to do ("This note no longer exists. Keep its text before loading current progress."), and re-validates through `normalizeProgress`. 03-WORKED-CHANGE.md tells the learner to verify this in a debugger: "keep references to both objects and compare their bodies after the function returns."
- The editor captures its base snapshot rather than re-reading at submit, and the course explains why: "It captures `progress` as the editor base… using the newest parent snapshot at submission time could disguise that the user edited an older record." `src/components/LearningNotes.tsx:15` (`const [base, setBase] = useState<GameProgress | null>(null)`) and `:73-74` (`updateNote(base, input)`) match, and `:138` even renders "Editing from revision {base.revision}" to the user.
- Validation is taught as the authoritative boundary, not as a form nicety: "Do not merely add an HTML `maxLength`; imported JSON bypasses that control." (03-WORKED-CHANGE.md). The tests back it — `src/game/storage.test.ts:76-87` is an `it.each` over nine malformed patches (`{ xp: NaN }`, `{ xp: -1 }`, `{ completedMissions: ["m1","m1"] }`, `{ activityDates: ["2026-02-30"] }`, `{ extra: "unsupported" }`, …) each asserting `normalizeProgress` throws.
- Corrupt data is preserved rather than clobbered: `storage.test.ts:66-75` asserts that after `loadProgress` throws on `"{broken"` or `'{"version":2}'`, `f.raw()` is still byte-identical. That is a real reliability behavior most tutorials never mention.
- Verification counts reconcile exactly once `it.each` expansion is accounted for (36), and Astra *under*-claimed rather than over-claimed the browser count. VERIFICATION.md also volunteers its own correction: "The review fixture required correction from `dueAt` to the existing `due` field; its focused rerun passed."

## Problems found (evidence required)
- **[D4]** There is no server, no HTTP, no SQL and no transaction in this project — persistence is `localStorage` coordinated by `navigator.locks`, and VERIFICATION.md says so ("no server authentication, SQL transaction layer, deployment verification, distributed concurrency guarantee"). The transferable parts are real (identity vs. content, schema as the trust boundary, revision-guarded writes, draft recovery, pagination interacting with deletion), but a learner finishes with no experience of request validation, authorization, migrations or database concurrency. Web Locks is also an unusual model to generalize from: `src/game/storage.ts:8` falls back when `navigator.locks` is absent, and the limits admit "a script that ignores this protocol can still overwrite storage."
- **[D5]** The course's setup section (`astraupskill/README.md`) gives `npm ci` and `npm run dev` only. The browser suite it later tells you to run needs `npx playwright install chromium`, which appears only in VERIFICATION.md — chapter 9 of 9. `package.json` also pins to unusually new majors (`typescript ^7.0.2`, `vite ^8.2.2`, `vitest ^5.0.0`, React 19.2) with caret ranges, so a fresh `npm install` months later will not reproduce the verified toolchain; only `package-lock.json` protects `npm ci`.
- **[D6/context, not a fault of Astra]** The project has drifted since delivery. `src/game/drafts.ts`, `drafts.test.ts` (15 further model tests), `lesson.ts`, `catalog.ts`, `components/Dashboard.tsx`, `LessonReader.tsx`, `MissionScreen.tsx` and a modified `tests/learning.spec.ts` (16 tests, four beyond Astra's 12) are all dated 2026-09-11, whereas Astra's files are dated 2026-09-09 01:38 and none of the Sep-11 files appear in `deliveries/a9672affc47e.json`. Anyone auditing the counts against today's disk will see 51 model cases and 16 browser tests and wrongly conclude the course under-reports. The course has no way to say "as of this commit."
- **[D8]** At 3,914 words this is the thinnest course in the batch, and the framing paragraphs are close to the batch template — `astraupskill/README.md`'s "Allow several focused sessions. A useful session produces a small diff, a reproducible check, and a short explanation of one tradeoff" is the same move as `e15/astraupskill/README.md`'s "Allow several focused sessions. Do not measure progress only by files read." The technical chapters are specific; the scaffolding around them is not.
- **[D7]** 01-CODEBASE-MAP.md is 368 words for an app that now spans a 334-mission archive, a game engine, a worker-based lab, a schema module and the notes feature. A junior will not know which of the ten `src/game/` modules are in scope for the course.

## One-paragraph summary for the index
The only project in this batch that is already on the target stack — React 19, TypeScript, Vite, Vitest, Playwright — and it teaches the client half of CRUD properly: a notes feature with stable identities, search, pagination and confirmed deletion, backed by pure immutable domain functions, a schema that is the authoritative boundary ("imported JSON bypasses `maxLength`"), a revision check that throws before `setItem` so a rejected save writes nothing, and a losing tab that keeps its draft and can export it before loading current data. Test counts are honest to the case (36 model cases once you expand the two `it.each` blocks; the browser count was under-claimed, not inflated), and the app even preserves corrupt stored bytes instead of clobbering them. What is missing is the server: no HTTP, no SQL, no authorization, no migrations — persistence is localStorage coordinated by Web Locks. Take it as a two-to-three hour elective on form state, validation boundaries and conflict UX in React, ideally *before* the Prisma/Postgres projects, and treat everything it teaches about concurrency as a warm-up for doing the same thing in a database.
