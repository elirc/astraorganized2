## What Astra did well
- **Verification honesty is the best in the batch.** `astraupskill/evidence.json` arithmetic is exact (13 + 28 + 17 + 3 = 61, matching the claimed `count: 61`), the xUnit count on disk matches exactly, and `VERIFICATION.md` opens with "do not infer completion from the presence of a test script". The limits list even confesses a failed cleanup that left a stray temp SQLite file outside the project and a blocked bundle deletion — an agent that admits its own housekeeping failure is worth trusting on the rest.
- **The CRUD curriculum coverage is exactly on target.** Optimistic concurrency via strong ETags (`HrisApi.cs:22` `ETag(Guid id, long version) => $"\"{id:N}-{version}\""`), idempotency receipts (`HrisApi.cs:46-65`, including an `Idempotency-Replayed: true` header and a 409 on key reuse with a different body), pagination with a `limit=101 → 422` bound, authorization rechecked *before* a receipt replay, and a real SQL transaction wrapping every mutation (`HrisApi.cs:30-31`, `101`).
- **Pedagogy is genuinely predict-run-change-verify.** `05-PRACTICE.md` Ex.1 says "Predict the HTTP status and whether any row, audit or receipt should commit. Run those requests … and compare"; the README step 5 tells the learner to "deliberately make one regression in a private practice copy and identify the test that catches it"; exercises are explicitly labelled "exercises, not claims that the features are already implemented", with solutions in a separate file.
- **`03-WORKED-CHANGE.md` teaches from an honest bug report.** It names the original defects precisely (a one-day 9,999-hour request accepted; an approval attached with a caller-supplied `Guid` treated by EF as an *existing* row, so `SaveChanges` threw a concurrency exception) and corrects a tempting over-claim: "The balance remained unchanged because that SaveChanges rolled back. The correct observation is 'approval failed'; a negative balance was not observed." That EF-tracking explanation is technically correct and is the single most valuable paragraph in the course.
- `scripts/check_api.py` is not a smoke test — it is a real black-box regression suite against live Kestrel/EF/SQLite that asserts status codes, projection shapes, cross-role visibility, and (line ~14 of the deliberate-failure section) that a *late receipt insert failure rolls back earlier domain SaveChanges*. That is a harder thing to prove than most xUnit suites in this batch attempt.

## Problems found (evidence required)
- **[D7][D2] The rewritten server is code-golfed and anti-idiomatic — the biggest problem with this course.** The original `server/Nethris.Api/Program.cs` was **502 lines** of idiomatic minimal-API endpoints; it is now **63 lines** plus a **194-line** hand-rolled dispatcher, `HrisApi.cs`, that routes by `http.Request.Path.Value!.Trim('/').Split('/').Skip(1)` and packs several statements per line:
  ```csharp
  await using var db = database.Create(); await db.Database.OpenConnectionAsync();
  ...
  await transaction.CommitAsync(); await Send(http, response, path == "setup" ? 201 : 200); return;
  ```
  (`HrisApi.cs:29`, `:37`). There is no `MapGet`/`MapPost`, no `[FromBody]` model binding, no `[ApiController]`, no filter/middleware pipeline for validation. A junior whose goal is *ASP.NET Core CRUD* will finish this course fluent in Astra's bespoke micro-framework and no more able to build a normal ASP.NET API than before. The same compression hit the client: `client/src/App.tsx` 543 lines → `client/src/Workshop.tsx` 174 lines.
- **[D2] "No regressions" is unverifiable at this scope.** This is a rewrite, not a bounded change: `server/Nethris.Api/Data/SeedData.cs` went from 124 lines to an 8-line class whose only method `throw`s `InvalidOperationException`, and `Contracts/Contracts.cs` from 110 lines to 7. 13 xUnit tests is thin cover for 180 touched files; 45 of the 61 "tests" are Python scripts that are not part of any `dotnet test` run, so CI for this repo proves 13 cases.
- **[D5] The verification story needs three toolchains.** `VERIFICATION.md` and `04-TESTING-AND-DEBUGGING.md` require .NET 10 SDK (pinned in `global.json`, good), Node/npm for the locked client, *and* Python + a Chromium install (`scripts/requirements-browser.txt`) for 45 of the 61 checks. A junior on a fresh machine will get 13/61 of the evidence without extra setup, and the course does not say so up front.
- **[D3] minor** `05-PRACTICE.md` has 6 exercises for a project this large, and Ex.6 ("Design approved PTO cancellation") is design-only with no acceptance criteria to test against, unlike Ex.2 which has a good explicit criteria list.

## One-paragraph summary for the index
Nethris is the most complete and most honest .NET CRUD course in this batch: it covers, on running code, the things a junior actually gets wrong in production work — optimistic concurrency with `If-Match` and strong ETags, idempotency keys with replayable creation receipts, transactional writes across domain + audit tables, role-sensitive field projection, pagination bounds, and a two-stage approval with a distinct-reviewer rule. The evidence is unusually trustworthy (counts reconcile exactly, screenshots exist, limits admit the agent's own cleanup failures), and the worked change is built from a correctly-diagnosed EF Core tracking bug rather than an invented one. Its serious flaw is that the rewritten server compressed a 502-line idiomatic minimal-API `Program.cs` into a 194-line hand-rolled path-splitting dispatcher with multiple statements per line, so the code you read is not the ASP.NET Core you will write at work, and only 13 of the 61 claimed checks are xUnit tests. Do it for the *concepts* — and read the fix list above before treating its routing code as a model. Budget 15-20 hours.
