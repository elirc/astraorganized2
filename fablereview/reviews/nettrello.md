## What Astra did well
- **The PATCH lesson is correct .NET and correct HTTP**, which is rare. `Contracts/BoardDtos.cs` uses non-nullable `JsonElement` properties precisely because `JsonValueKind.Undefined` is the only way `System.Text.Json` can distinguish "property absent" from "property present and null" without a custom `Optional<T>` converter — and the code comments say exactly that: *"Nonnullable JsonElement preserves Undefined (omitted) from an explicit JSON null. This is essential for PATCH semantics."* `[JsonUnmappedMemberHandling(JsonUnmappedMemberHandling.Disallow)]` (a real .NET 8 attribute) closes the "silently ignored typo'd field" hole, and `ReadPriority` correctly follows `Enum.TryParse` with `Enum.IsDefined`, because `TryParse` happily succeeds on out-of-range numeric strings.
- **The move-ordering fix is a genuine data-loss bug fix.** The backup `Board.cs` did `var card = sourceColumn.RemoveCard(cardId); card.MoveTo(position, now); var targetColumn = FindColumn(targetColumnId);` — so a bad `targetColumnId` threw *after* the card had already left its column, in an in-memory aggregate. The new order (find target → `Guard.NonNegative(position)` → same-column branch → capacity check → remove → insert) makes every rejection a no-op. `BoardColumn.AddCard` was likewise corrected from "insert then `EnsureCardLimit()`" to `EnsureCapacityForInsert()` first.
- **The checks prove *absence of partial mutation*, not just that an exception was thrown.** `tests/NetTrello.Checks/Program.cs` serializes the whole column/card graph into a `Describe(...)` string before each rejected operation and asserts byte equality afterwards: `ExpectDomain(() => memberBoard.MoveCard(first.Id, target.Id, 0, now), "column.card_limit"); ExpectEqual(beforeMove, Describe(memberBoard), "full target must not remove the source card");`. That is the right assertion for this class of bug and is stronger than most xUnit suites in the batch.
- **Pedagogy is real predict-run-verify.** `05-PRACTICE.md` Ex.1: "Predict every field after the response"; Ex.2: "predict status, problem code, and whether board version changes"; Ex.3 asks for "source order, target order, card position, timestamp, and version before and after each rejection"; the chapter then requires "an expected-state table with response, writes, version, timestamps, and visible fields" before reading the separate solutions file. Ex.7 ("Decide which failures belong to domain tests, service tests, repository tests, and HTTP tests. Do not claim an HTTP status from a pure domain assertion") teaches test-boundary discipline directly.
- **Verification honesty is the best in the batch on the hardest axis — disclosing its own coverage gaps.** `results.json` states `"testCountMeaning": "one domain/service console harness plus one HTTP script; not separately discovered unit tests"`, `VERIFICATION.md` says "It must not be inferred from source inspection" and "do not silently call that a net8 runtime test", and the delivery limits admit *"the console failed-move snapshot omits board Version and UpdatedAt"* — i.e. it names a field its own assertion does not cover.

## Problems found (evidence required)
- **[D2][D7] The check harness is a fail-fast console app, not xUnit.** `tests/NetTrello.Checks/Program.cs` is top-level statements with hand-rolled `ExpectEqual`/`ExpectDomain` helpers that `throw new Exception(...)`. The first failure aborts the process, so the remaining ~35 assertions never run and a regression can mask others; there is no per-case name, no TRX, no `dotnet test`, and the delivery can only report `passedTests: 1`. A learner finishes this course without writing a `[Fact]`.
- **[D2] The React client — the main PATCH caller — is never exercised.** The delivery limits admit "no client build or browser check ran". `client/src/components/CardEditor.tsx:24-34` is the only code path that builds the six-field payload and `client/src/api/boardClient.ts:84-92` the only one that sends it; neither has a test, and the course's compatibility claim ("The existing React editor sends all six fields") rests on reading, not running.
- **[D5] The two-TFM setup is a stumbling block.** `VERIFICATION.md` says "The API targets .NET 8 and the check executable targets .NET 10; install the .NET 10 SDK", and `tests/http-regression.ps1:5` sets `$env:DOTNET_ROLL_FORWARD = 'Major'` to run the net8 API on a net10 runtime. This is disclosed honestly but means the HTTP evidence is not a net8 result, and the whole HTTP tier requires Windows PowerShell — there is no cross-platform equivalent.
- **[D7] minor** 4,200 words is the thinnest course in the batch, and it front-loads intermediate material (`JsonElement` value kinds, `JsonUnmappedMemberHandling`, clone-on-write repositories, optimistic `X-Board-Version`). `02-CONCEPTS.md` carries most of the definitional load for all of it in 454 words.

## One-paragraph summary for the index
A short, sharp, technically correct course on the single most commonly-botched CRUD operation: HTTP PATCH. It shows why a naive DTO turns "field omitted" into "field cleared", and fixes it the right way in `System.Text.Json` using non-nullable `JsonElement` properties and `JsonValueKind.Undefined`, with `[JsonUnmappedMemberHandling(Disallow)]` for typo'd fields and `Enum.IsDefined` after `Enum.TryParse` for enums — every one of which is idiomatic .NET a junior will reuse immediately. It pairs that with a real aggregate-ordering bug fix (the old `MoveCard` removed a card from its source column before validating the destination) and checks that snapshot the whole board before a rejected operation to prove nothing partially mutated. The exercises genuinely demand predictions and expected-state tables before the separate solutions chapter, and the verification record is unusually candid — it even names a field its own assertions do not cover. The catch: the "tests" are a fail-fast console app and a PowerShell script rather than xUnit, and the React client that actually sends the PATCH was never built or tested. Do it; budget 4-6 hours.
