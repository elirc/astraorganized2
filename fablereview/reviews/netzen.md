## What Astra did well
- **The headline bug is a genuinely important one and rarely taught: authorization applied *after* pagination.** The backup `SearchTickets.cs` did `var unpagedCriteria = criteria with { Page = 1, PageSize = 100 }` — read the first 100 rows, *then* filter by `Permissions.CanReadTicket`, *then* paginate. A customer whose only ticket sat at store-position 101 got an empty result, and the reported `Total` was wrong. This is the same class of bug that produces short pages and phantom counts in every real CRUD app, and juniors reproduce it constantly.
- **The `ReplaceTags` test is the best single test in the batch.** `TicketSafetyTests.cs:19-31` builds a deliberately-throwing iterator — `IEnumerable<string> Broken() { yield return "changed"; throw new InvalidOperationException("enumeration failed"); }` — and then asserts both `ticket.Version` and `ticket.Tags` are unchanged. That proves the *actual* semantic of the fix (deferred LINQ execution means `_tags.Clear()` followed by `AddRange(lazyQuery)` can half-apply), rather than asserting that a method was called.
- **The search test is a real fixture, not a toy.** It seeds 121 tickets across two 100-row source pages, asserts the single customer-owned ticket `T-000001` is still found with `Total == 1`, then searches for `"INTERNAL-ONLY-MARKER"` (the text of an `Internal`-visibility comment) and asserts zero results. Two distinct leak classes covered by one fixture.
- **The SignalR redesign teaches the right instinct.** Broadcasting a `TicketSummaryDto` to a shared `"inbox"` group hands every connected client data it may not be authorized to see; replacing it with a payload-free `"tickets.changed"` signal forces each client to refetch through the authorized endpoint. `07-TRACE-LAB.md` is explicit that this does not buy durability: "a reconnect callback proves that this client attempts to rejoin and refreshes after `JoinInbox`; it does not prove that a notification emitted during downtime was durably replayed."
- **`VERIFICATION.md` polices the reader against a specific over-read**: "This build proves compilation and bundling. It does not mount `App`, open a SignalR connection, assert browser DOM behavior, or run a live HTTP test server. **Do not invent a frontend unit-test pass from the build.**"

## Problems found (evidence required)
- **[D2] The enum guard is inconsistent, and Astra knew it.** `UpdatePriority` now starts with `if (!Enum.IsDefined(priority)) throw new DomainException(...)`, but `Ticket.Create` still takes a `TicketPriority priority` parameter with no such guard — so `(TicketPriority)99` is rejected on update and accepted on create. `VERIFICATION.md` admits this ("The sample does not prove … a creation-time priority enum guard") and the delivery limits repeat it ("Creation-time priority fallback remains unchanged"), but it was shipped that way. A junior copying this will learn a half-applied invariant.
- **[D2] The new search loop is a pattern that will hurt someone who copies it.** `SearchTickets.cs` now does `do { searchResult = await _store.SearchAsync(criteria with { Page = sourcePage, PageSize = 100 }, …); visible.AddRange(…); sourcePage++; } while (sourcePage <= Math.Max(1, (int)Math.Ceiling(searchResult.Total / 100d)));` — i.e. it pulls the **entire matching table into memory on every search request** just to apply authorization. Correct for a small in-memory store; catastrophic against EF Core/SQL. `VERIFICATION.md` does say "Future pagination should push authorization into the query", but that one sentence is buried in the limits rather than being taught as the lesson, and no chapter shows what pushing the predicate into the query would look like.
- **[D2] A behavioural regression was introduced in the hub effect.** The dependency list went from `[selectedId]` to `[selectedId, filters]` (`App.tsx`), so the cleanup now runs `connection.stop()` and a fresh `connectTicketHub(...)` is created **every time the user changes a filter**. `07-TRACE-LAB.md` describes this as normal ("the effect cleanup stops the old connection and a new effect captures current filters") without ever asking whether tearing down a WebSocket on each keystroke-driven filter change is acceptable. The idiomatic fix — hold `filters`/`selectedId` in refs and keep the connection effect on `[]` — is never mentioned.
- **[D2] Three quarters of the change is untested.** The SignalR notifier change and the entire `App.tsx` request-sequencing change have no test at all; `package.json` adds `@types/react` but no test runner. The delivery limits state this ("no live hub, HTTP server or browser tests"), which is honest, but it means only the two domain fixes and the search fix are actually proven.
- **[D3] `05-PRACTICE.md` narrates the delivered implementation rather than setting a task.** Its third paragraph walks through exactly what was built — "In `App`, the effect keeps `active`, `detailRequest`, `selectedId`, and `filters` in its closure… Cleanup sets `active = false` and stops the connection. The dependency list includes `[selectedId, filters]`" — before asking **Exercise 5** to "rewrite a hypothetical `tickets.changed` callback". The answer is on the same page as the question.

## One-paragraph summary for the index
Do this course for one lesson that most juniors have never been shown: **authorization must be applied before pagination, not after**. The original handler read the first 100 rows, then filtered by permission, then paged — so an authorized user's results past row 100 silently disappeared and the reported total was wrong, and Astra's 121-ticket fixture proves the fix. It pairs that with two other sharp ideas: a deferred-LINQ trap (`_tags.Clear()` followed by `AddRange(lazyQuery)` can half-apply, demonstrated with a deliberately-throwing iterator) and a SignalR redesign that stops broadcasting ticket payloads to a shared group in favour of a payload-free invalidation that forces each client to refetch through its own authorized endpoint. The evidence is scrupulous — 3 claimed, 3 on disk, 3 in the TRX, with an explicit warning not to read the frontend build as a test pass. Weigh two things: only three of the four changes are tested (the SignalR and React work has no test at all), the new search loop pulls the whole table into memory and should not be copied into an EF Core project, and the hub `useEffect` now reconnects on every filter change. Budget 4-6 hours.
