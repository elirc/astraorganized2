## What Astra did well
- The audit-log fix is the kind of bug juniors should learn to spot. The backup `bulkStatus` inserted `{ before: null, after: { status } }` for every row — an audit trail that records the intent, not the change. The new loop captures the locked `before` row and the returned `after` row per record, and the test asserts `audit.before.status === "todo"` and `audit.after.status === "in_progress"`.
- Desired-state semantics are implemented and asserted. Archive twice, restore twice: the test counts `audit_log` rows before and after the repeat and asserts the count is unchanged, which is a much better assertion than "returns 200".
- The additive migration is the correct shape for a schema change on live data, and the fallback is honest about what it cannot know: `status: before.status_before_archive || "todo"` with the report noting "the migration does not invent a historical state it cannot know."
- The React half is real CRUD-frontend content: `const sequence = ++refreshSequence.current; … if (sequence !== refreshSequence.current) return;` in `client/src/App.tsx` is a correct stale-response guard, and the failed-save path preserves the draft and surfaces `error` instead of clearing the form.
- The self-assessment is unusually candid: "The version increments on change, but this is not yet optimistic concurrency: a client does not send an expected version. A row lock serializes writes; it does not detect a stale full-form edit."
- All 69 substantive code lines in `03-WORKED-CHANGE.md` matched verbatim against the project's `.ts`/`.tsx` sources (69/69).

## One-paragraph summary for the index
An enterprise-flavoured task CRUD API where archiving lost the record's previous workflow state, restoring set a status that did not exist in the enum, and bulk status changes wrote audit rows with `before: null`. The fix teaches four things worth knowing: an additive migration to store what you will need to undo, desired-state commands that make a repeated archive a no-op instead of another history row, locking every target of a batch in ID order and rejecting the whole batch atomically when one is missing, and a React `useRef` sequence counter that stops a slow earlier response from overwriting a newer list. The four tests are real HTTP tests against a disposable Postgres schema and assert audit contents and unchanged history counts, not just status codes. Do this course — but do **only** this one: projects 17, 18, 19 and 20 ship the same 8.4k words with the nouns swapped.
