## What Astra did well
- The security thesis is right and well executed: route guards are not a trust boundary for a service that other code can import. `src/services/feature-config-service.ts` now starts each mutating method with `assertPermission(actor.role, ...)`, and `src/lib/auth/permissions.ts:38` changed `rolePermissions[role].includes(...)` (which *threw* on an unknown role) to `(rolePermissions[role] ?? []).includes(...)` — fail closed instead of crash.
- `withMockTransaction` (`src/lib/data/mock-db.ts:228`) is a small, honest piece of teaching machinery: clone the state, run a synchronous callback, keep the clone only if it returns, restore the original on throw, and explicitly reject a thenable because "a promise could schedule writes after the clone was committed."
- The rollback test is the real thing, not a mock-call assertion. `tests/feature-platform.test.ts:108` stubs `auditService.record` to throw, then asserts `assert.deepEqual(globalThis.__W24_MOCK_DB__, before)` on a whole-database `structuredClone` **and** that the stale cache entry survived (`readCachedActiveVersion(...)?.id === old.id`), and then that a real publish afterwards succeeds. That single test pins atomicity, ordering, and cache-freshness at once.
- `tests/feature-platform.test.ts:137` invokes the actual POST route handler with a real `Request` carrying the body `"{bad"` and asserts 400 plus an unchanged database — a genuine Next.js route-handler test, not a service call dressed up as one.
- `06-SOLUTIONS-AND-REVIEW.md` ends with the single most transferable habit in the whole batch: "mark each statement as proven, inferred, or untested", with three worked examples including one the author marks *untested* ("Two workers cannot publish concurrently").
- `tsconfig.json` was updated to `"exclude": ["node_modules", "astraupskill/original"]`, so the shipped pre-change snapshots do not pollute typecheck — a trap that the sibling e13 project in this batch fell into.

## Problems found (evidence required)
- **[D1]** The worked-change code block is fabricated. `03-WORKED-CHANGE.md` presents "The key implementation is in feature-config-service.ts ... The important shape is:" followed by `featureConfigRepository.retireActiveVersions(featureConfigId)`, `featureConfigRepository.updateVersion(versionId, {...})`, `featureConfigRepository.update(featureConfigId, {...})` and `auditService.record({ action: "PUBLISHED", ..., actorId: actor.id })`. None of these exist: `src/repositories/feature-config-repository.ts` exposes `updateVersion(version)` (single spread argument) and `updateConfig(config)`, there is no `retireActiveVersions` or `update`, the audit action is `"VERSION_PUBLISHED"`, and `record` takes `actor`, not `actorId`. The disclaimer "The actual implementation includes its full domain fields and checks" does not cover invented method names.
- **[D6]** `VERIFICATION.md` names `w24_tests_20260913i.json` as the passing test record. That record's command is `node --conditions=react-server --import tsx --test tests/feature-platform.test.ts` and its log reads `# tests 9`. The delivery's headline is 11, which only the later `w24_tests_final_20260913` run (which adds `src/lib/auth/security-boundary.test.ts`) achieves. The course also never states a test count at all, saying only "The test command reports nonempty passing Node tests."
- **[D5]** Consequently the documented reproduce command runs 9 of the 11 delivered tests; `src/lib/auth/security-boundary.test.ts` appears in no course command. There is also no `test` script in `package.json` (`dev`/`build`/`start`/`lint` only), so there is nothing a learner or CI can just call.
- **[D2]** Formatting was mangled by the transaction refactor and never cleaned: `src/services/feature-config-service.ts` now has one-line `if (currentlyActive) featureConfigRepository.updateVersion({` bodies and an `auditService.record({` block left at the pre-refactor indentation inside the new callback. Lint passes, but the centerpiece file of the course reads as a botched merge.
- **[D2]** The audit projection hardcodes a role literal — `actor && actor.role === "SUPPORT_VIEWER" ? [] : auditService.listByFeatureConfigId(...)` (`feature-config-service.ts:75`) — in a codebase that has a permission map right there. This is the policy drift the course's own concepts chapter warns about; it should be `hasPermission(actor.role, "audit:read")`.
- **[D2]** The `Suspense` change in `src/app/layout.tsx` wraps both `<ActorSwitcher>` and *all* `{children}` in `<Suspense fallback={null}>`. `01-CODEBASE-MAP.md` justifies it in one sentence ("a server-rendered dynamic read must have a fallback before the route can stream") but never names the error it fixes (a dynamic-API / `useSearchParams` CSR bailout), and `fallback={null}` for the whole page means a blank screen instead of a skeleton. Delivery limits also concede it was never checked in a browser.
- **[D2/D4, unstated breaking change]** Restricting `gte`/`lte` to numeric `user.usageCount` means any *already stored* rule document with a string threshold now fails `createVersionSchema` on re-save, and the evaluator will return `false` where it previously coerced. No chapter and no limit mentions the migration consequence.
- **[D4, context]** `@prisma/client ^7.7.0` is in `package.json` and a `prisma/` directory exists, but every "transaction" here is a `structuredClone` of an in-memory object. The course is honest that this is not SQL, yet a learner looking for Prisma transaction practice will not find any in this project.

## One-paragraph summary for the index
A feature-flag platform used to teach four things a CRUD engineer needs: authorize at the service, not only at the route; validate shape before it becomes runtime behavior; keep every write of a multi-record transition inside one boundary and invalidate the cache only after it commits; and never let an internal error message reach the client. The rollback test is excellent — it stubs the audit writer to throw and then deep-compares the entire database plus the cache — and the solutions chapter teaches a review habit (label each claim proven / inferred / untested) that transfers to any codebase. Two things need fixing before a junior uses it: the worked-change chapter shows a publish implementation with repository methods that do not exist in this project, and the documented test command runs 9 of the 11 delivered tests. Also note the "transaction" here is a `structuredClone` of an in-memory store, not Prisma or SQL.
