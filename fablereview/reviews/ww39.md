## What Astra did well
- The code change is a genuine reliability improvement, not cosmetics. `src/repositories/ticketRepository.ts:49-90` replaces `prisma.ticket.update({where:{id}})` with `prisma.ticket.updateMany({where:{id, escalatedAt: null, status: expectedStatus, ...}})` and returns `null` on a zero-row result; the services translate that null into a `ValidationDomainError` (`src/services/ticketService.ts:164`, `:243`). This is textbook optimistic concurrency and exactly the CRUD lesson a junior needs.
- The Prisma transaction claim is real and matches the course. `ticketRepository.markEscalatedWithAudit` opens `prisma.$transaction(async (tx) => {...})`, does the conditional `tx.ticket.updateMany`, bails with `null` if `result.count !== 1`, then `tx.auditLog.create(...)` and re-reads through `tx`. The course's claim in `03-WORKED-CHANGE.md` ("If the audit insert rejects, Prisma rolls the routing update back") is accurate for this code.
- Honest limits. `VERIFICATION.md` states plainly that "A unit suite using repository fakes … does not prove PostgreSQL transaction rollback, isolation, or cross-process locking," and `06-SOLUTIONS-AND-REVIEW.md` calls out that a fake that flips a `claimed` boolean "proves only that the fake remembers a boolean." That self-criticism is rarer than it should be in this fleet.
- The subtle `undefined` vs `null` assignment semantics lesson (omitted `assigneeId` preserves, explicit `null` clears) is both implemented (`ticketService.ts:204`) and taught with a prediction exercise — a very good junior CRUD trap.

## Problems found (evidence required)
- **[D1]** The model solution given for the permission fix does not match the shipped code and is *wrong*. `06-SOLUTIONS-AND-REVIEW.md`: "The permission solution is intentionally small: `roleCapabilities[user.role]?.includes(capability) ?? false`". The actual code (`src/lib/auth/permissions.ts:61-67`) uses `Object.prototype.hasOwnProperty.call(roleCapabilities, user.role)` plus `Array.isArray`. The optional-chaining version the course recommends would **throw** on the course's own `it.each(["constructor","toString","__proto__"])` test (`src/tests/permissions.test.ts:58`), because `roleCapabilities.constructor` is a function, not `undefined`. A junior who follows the printed solution fails the shipped test suite.
- **[D1]** `04-TESTING-AND-DEBUGGING.md` repeats the same error: "`hasCapability` therefore uses optional lookup and returns false for an unrecognized role." It does not use optional lookup.
- **[D6]** `VERIFICATION.md` (second section): "The full project command in the delivery record executes the complete six-file suite." There are **seven** test files, and the delivery JSON itself says `"testFiles": 7`.
- **[D6]** `VERIFICATION.md`: "The focused regression command executes eight tests in two files after the repair: six escalation cases and two permission cases." `src/tests/permissions.test.ts` contains five tests (1 pre-existing + 1 new + a 3-case `it.each`), so that command runs 11, not 8. The headline count of 20 *is* correct and matches the evidence JSON, so this is sloppiness rather than inflation — but it is exactly the kind of number a learner will check.
- **[D3][D7]** Zero fenced code blocks in the entire course: `grep -c '```' astraupskill/*.md` returns 0 for all nine files. 3,800 words of unbroken paragraphs with no listings, no bullets, no diagrams. "Before: `markEscalated()` returned a ticket" style inline comparisons are the only code the learner sees. For a course whose whole point is a `updateMany` predicate and a `$transaction` callback, not showing them is a serious pedagogy gap.
- **[D7]** Agent-process leakage into learner-facing text. `VERIFICATION.md`: "Keep dependencies out of the manifest and preserve the canonical project until root applies the reviewed delivery… The root agent applies the frozen manifest after review." A junior has no manifest, no root agent, and no canonical project. Same file also tells the learner to compare hashes against `baselines/1c688787ace6.json` and read `checks/1c688787ace6/results.json` — neither path exists anywhere under the project.
- **[D5]** No database story. The app is Prisma/PostgreSQL with `prisma/seed.ts`, but no chapter gives `npx prisma migrate dev` / `db push` / seed / `DATABASE_URL` instructions, or a port. The only runnable commands are `npm test` and `npx tsc --noEmit`; a junior cannot actually run the app or exercise the cron escalation route they are told to trace.
- **[D2]** The change introduces `as any` casts into production code it is simultaneously teaching about: `ticketRepository.ts:66-67`, `:113-114` (`(input.assigneeId === undefined ? undefined : input.assigneeId) as any`). `04-TESTING-AND-DEBUGGING.md` tells learners "When a test uses `as any`, explain what boundary the fake is modeling" — but these are in the adapter, not a fake, and are unexplained.
- **[D3]** Every chapter file has two `# ` H1 headings (e.g. `03-WORKED-CHANGE.md` has "# Worked change" then "# Transaction boundary walkthrough"), i.e. a second pass was appended rather than integrated. Reading order inside a chapter is therefore not obvious.

## One-paragraph summary for the index
This is one of the better wave-2 code changes: it takes a Next.js 15 + Prisma support-desk app and converts naive `update({where:{id}})` writes into conditional `updateMany` compare-and-set claims, wraps the escalation claim and its audit row in a single `$transaction`, makes SLA deadline and rule selection deterministic, and makes the permission map fail closed on unknown roles — with 20 real Vitest tests that check the returned values, not just that a mock was called. If you want to learn optimistic concurrency, transactional audit writes, and the `undefined`-vs-`null` update trap on the Prisma/Next stack, the *code* here is worth reading carefully. The *course* is weaker: 3,800 words of unbroken prose with not a single code block, a printed "model solution" for the permission fix that contradicts the shipped code and would fail the course's own tests, two wrong test counts in VERIFICATION.md, and leftover agent-process jargon about manifests and "the root agent." Do it as an elective after the fixes above, and read `src/repositories/ticketRepository.ts` and `src/services/escalationService.ts` directly alongside the text.
