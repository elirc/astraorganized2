## What Astra did well
- **Verification honesty is the best in this batch.** `astraupskill/evidence/z1-tests-final-03.log` is the actual Node TAP output shipped inside the course folder; its tail reads `1..16 / # tests 16 / # pass 16 / # fail 0`. VERIFICATION.md links it relatively (`evidence/z1-tests-final-03.log`) so the learner can open it. It even discloses sequencing honestly: "The build preceded the final test-only assertion additions; production source did not change afterward."
- **A genuinely subtle limit is stated, not hidden.** `VERIFICATION.md` and `04-TESTING-AND-DEBUGGING.md` both say: "A clone may have been modified and discarded, so value equality is not proof that no in-memory mutation occurred." Most courses in this fleet would have sold `assert.equal(JSON.stringify(after), before)` as proof of "no partial writes." This one explains precisely what it does and does not prove. Same for "Service errors here are plain Error objects: the suite does not establish an HTTP status mapping."
- **The tests use the production store, not a fake.** `withIsolatedStore` sets `process.env.RAP_DATA_DIRECTORY` to a unique `os.tmpdir()` path, runs one serial test against the real `readDatabase`/`updateDatabase` modules, and `fs.rm`s the directory in `finally`. The delegation fixture is made relative to today (`activateMarcusDelegation`) so a stale seed interval cannot silently invalidate the scenario — that is a maturity signal.
- **The security fix is real and well-chosen.** `src/app/api/requests/[id]/status/route.ts` casts its JSON body with `as { action: ... }` and does no runtime validation at all, so the service layer really is the only line of defence; the course's whole emphasis on service-layer whitelists is therefore grounded, not theoretical. And the DTO fix (`const canReadInternal = user.id !== request.requesterId && canReadInternalComment(user)`) is applied to *both* `comments` and `timeline`, with a test that plants `SECRET-INTERNAL-MARKER` and asserts its absence in both collections.
- **Next.js details are correct where touched.** The route handler contract (`context: { params: Promise<{ id: string }> }`, awaited) is the right Next 16 shape, and `01-CODEBASE-MAP.md`'s "a route parses a request and calls the service" matches the actual `src/app/api/**/route.ts` layout. There are no server actions in this project and the course correctly does not claim any.

## Problems found (evidence required)
- **[D7][D8]** `06-SOLUTIONS-AND-REVIEW.md` is 2,578 words of the course's 5,252 — **49%** — and most of it is a verbatim dump of `tests/service-layer.test.ts` under the heading "## Complete service regression fixture" (the file is 674 lines). That file already exists in the repo two directories away. The headline "5,252 words" therefore overstates the amount of original teaching material by roughly a factor of two, and pasting the finished test file directly under the solutions invites copy-paste instead of the exercise's stated goal ("Extend the existing cases when practicing"). The chapter's own four solution paragraphs (the valuable part) are only ~450 words.
- **[D3]** The predict → run → change → verify loop is implicit rather than explicit. `05-PRACTICE.md` exercises say "assert that Marcus … is allowed" and "assert that Fiona … is denied" — the answer is given in the instruction. There is no "write down your prediction before running" step (contrast ww39's `05-PRACTICE.md`, which does this well). The learner is told the expected result, then told to assert it.
- **[D7]** Chapters are single unbroken prose blocks with no sub-headings (01, 03, 04, 07 have exactly one `#` and then 3-5 dense paragraphs). `02-CONCEPTS.md` is the exception and is noticeably easier to read because of its `## Work through the boundaries` split.
- **[D5]** Conflicting run location. `astraupskill/README.md`: "Run from this folder after dependencies are installed: `npm test` …" — `astraupskill/` has no `package.json`. `VERIFICATION.md` correctly says "Run from the z1 project root." A junior following the README in order hits the wrong directory first.
- **[D1, minor]** `package.json` lists `@prisma/client` ^7.6.0 and `prisma` ^7.6.0 as runtime dependencies, but there is no `prisma/` directory and no schema (`ls prisma` → not found), and nothing in `src` imports Prisma. The course never mentions this; `02-CONCEPTS.md` refers only to "a future database migration." Not Astra's bug, but a learner reading `package.json` will look for a database that does not exist, and the codebase map should say so.
- **[D2, minor]** The root `README.md` was rewritten wholesale (every line shows as changed in `diff -r backup project`) for what is functionally a two-line append of the course link — a line-ending/encoding rewrite. It also preserved the pre-existing broken absolute links (`/c:/Users/Owner/Desktop/z1/docs/architecture/README.md`), which now point at a path that no longer exists since the project moved under `_Organized Desktop/05 Numbered Experiments/`. Since Astra was editing that file anyway, those should have been fixed.

## One-paragraph summary for the index
Do this one. It is the most trustworthy course in B12: the fix is a real authorization bug (an approver at workflow step 2 could act while step 1 was still pending, because the policy scanned *all* pending rows instead of joining `request.currentStepIndex` with `approval.sequence`), the companion fix closes an internal-comment leak in both the `comments` and `timeline` DTOs, and the 16 tests run against the *production* JSON store in a disposable temp directory rather than a fake, asserting serialized before/after equality after every rejection. Crucially, Astra shipped the actual Node TAP log inside the course folder (`evidence/z1-tests-final-03.log`, 16 pass / 0 fail) and states its limits with unusual precision, including the genuinely subtle point that snapshot equality does not prove no in-memory mutation occurred. The one real weakness is padding: nearly half the course's 5,252 words is `tests/service-layer.test.ts` pasted verbatim into the solutions chapter, and the practice exercises hand you the answers instead of asking for predictions. Read chapters 01-04 and 07, do 05 without looking at 06, and skip the giant code dump.
