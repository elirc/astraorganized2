## What Astra did well
- **The central lesson — check-then-write races — is taught precisely and fixed correctly.** `02-CONCEPTS.md`: "A stale read outside the queue creates a check-then-write race: two calls can both see `convertedAt: null`, then each create a company, contact, deal, and event. Moving the check and construction into the callback means the second callback sees the first callback's converted lead and rejects without changing the file." The backup (`snapshots/service-before.ts.txt` / the diff) confirms the old code read the DB outside the queue and then issued five separate `saveX` calls; the new code does everything inside one `updateCrmDatabase((current) => ...)` and returns one value.
- **The filter-before-limit bug is a genuinely good junior trap.** Old: `db.activityEvents.slice(0, 8).map(...)`. New: `.filter(event => user.role !== "sales_rep" || ownerIdForEntity(...) === user.id).slice(0, 8)`. `02-CONCEPTS.md` explains the consequence exactly: "Taking eight rows and then removing foreign events can return fewer than eight owned events and can hide older owned work," and exercise 2 makes the learner compute both numbers (6 vs 8).
- **Astra explicitly marks which snippets are runnable and which are not.** `03-WORKED-CHANGE.md`: "The following is an **illustrative excerpt**, with builder names shortened for readability; the runnable implementation in `src/modules/crm/service.ts` … is the source of truth." `04-TESTING-AND-DEBUGGING.md` closes with "The examples above are copied from the test harness; snippets in other chapters marked illustrative are not additional tests." I have not seen another course in this fleet do this, and it directly prevents the inflated-test-count problem that shows up elsewhere.
- **Reproducibility is excellent.** `VERIFICATION.md` ships a PowerShell block with `$LASTEXITCODE` gating after every command ("Stop on the first failure; a successful later command must not hide an earlier failure"), states the expected result ("Expect five passing service tests with no skipped tests"), and links `evidence/verify-01.json` and `evidence/verify-01.log` — the log's tail is the actual Next build route table, which I read.
- **Limits are stated where they bite.** The delivery JSON limits include "Task/note target authorization reads occur outside the write queue, so this is request-time policy coverage rather than cross-process race protection" — i.e. Astra correctly identifies that its *own* fix is partial for tasks/notes even though it is complete for conversion. `02-CONCEPTS.md` repeats it: "This is atomic at the application value level… It is not a database transaction."
- **The tests exercise the real modules, not copies.** `tests/crm.test.ts` sets `CRM_DB_PATH` to an `mkdtemp` path *before* dynamically importing `../src/modules/crm/service`, writes a full synthetic `CrmDatabase`, and then calls `globalSearch`, `getDashboardData`, `createTask`, `addNote`, `convertLead` — with `Promise.allSettled([convertLead(...), convertLead(...)])` asserting exactly one fulfilled and one rejected, plus `deepEqual` on the whole database after denials.

## Problems found (evidence required)
- **[D2]** The ESLint "fix" is close to vacuous and adds a dependency it never uses. The change swapped `"lint": "next lint"` for `"lint": "eslint src tests next.config.ts eslint.config.mjs"`, and the new `eslint.config.mjs` enables exactly **two** rules: `@typescript-eslint/no-unused-vars` (error) and `@typescript-eslint/no-explicit-any` (**warn**). It does not extend `@typescript-eslint`'s recommended set and does not use `eslint-config-next` — which Astra nevertheless added to `devDependencies` (`"eslint-config-next": "^15.3.1"`). So `npm run lint` now passes trivially, all Next-specific rules (React hooks, `no-img-element`, etc.) are gone, and there is an unused dependency in the lockfile. Astra *does* disclose the coverage gap ("Next plugin recommended lint rules are not enabled, as recorded by the build warning"), which is why this is a D2 rather than a D6 finding — but the delivery summary's framing, "Replaces the unusable `next lint` command with a finite TypeScript ESLint flat configuration," oversells it.
- **[D2][D1]** The one Next.js-specific design decision Astra made is essentially undocumented. `src/modules/auth/session.ts` was changed from top-level `import { cookies } from "next/headers"` / `import { redirect } from "next/navigation"` to `const { cookies } = await import("next/headers")` inside each function — because `src/modules/crm/service.ts:3` imports `canEditOwnedRecord` from that same module, so a top-level `next/headers` import would break `tsx --test`. The course mentions this only as five words in `VERIFICATION.md` ("and the session import boundary") and never in a chapter. This is a teachable moment (a module that mixes pure role predicates with Next runtime APIs is hard to test), and the cleaner fix — extracting `canManageAdmin` / `canWriteOwnedRecords` / `canEditOwnedRecord` / `isReadOnlyUser` into `src/modules/auth/policy.ts` — is never discussed. Instead, production code now pays a dynamic-import cost on every cookie read to satisfy a test runner.
- **[D2, minor]** `requireUser` now ends with `redirect("/login"); throw new Error("redirect did not terminate the request");`. In Next.js `redirect()` throws internally, so that line is unreachable in the app; it exists only to satisfy the `Promise<DemoUser>` return type. It is defensible but unexplained, and a junior reading it will not know why.
- **[D3][D7]** Five of nine files contain no code at all (`grep -c '```'` returns 0 for `01-CODEBASE-MAP.md`, `02-CONCEPTS.md`, `05-PRACTICE.md`, `07-TRACE-LAB.md`, `README.md`). `02-CONCEPTS.md` describes `updateJsonFile`'s promise-per-path queue in prose across a full paragraph without ever showing the ~8 lines of `src/server/json-store.ts` that implement it — which is the single most important mechanism in the course.
- **[D3]** No failure-injection lab. Every course in this batch that scores well on pedagogy makes the learner *break* something (ww5 spies on `auditService.log` to force a rollback; z1 clears `riskMitigation`). Here the exercises are all read-and-predict plus one concurrency trace; there is no exercise that, say, makes `writeJsonFile` throw mid-conversion to show what the JSON store cannot protect. Given that "direct `fs.writeFile` is not crash-safe" is one of the four stated limits, this is the obvious missing exercise.
- **[D2, scale]** Five tests is thin for the surface changed (search filtering, dashboard filtering, task auth, note auth, conversion atomicity, retry). They are good tests, but e.g. there is no test that a founder *can* attach a task to a foreign lead, and no test of the `analyst` read path beyond one assertion.

## One-paragraph summary for the index
A small Next.js App Router CRM with a JSON file store, used to teach the single most common CRUD concurrency bug: reading a record, deciding it is safe to act, and then writing — with the read outside the serialization boundary. Astra's fix collapses `convertLead`'s stale read plus five separate saves into one `updateCrmDatabase` callback that re-reads the lead inside the queue and returns one complete database value, so two simultaneous conversions produce exactly one company/contact/deal/event graph and the loser gets "Lead has already been converted." It also fixes a subtler bug you will meet again — filtering by ownership *after* `slice(0, 8)` silently hides older owned rows — and adds target-ownership checks before task and note writes. Everything I spot-checked matched the code, the five tests run the real service modules against a disposable `CRM_DB_PATH` fixture with `Promise.allSettled`, and Astra ships the actual verification log plus byte-exact `*-before` snapshots and, unusually, labels which code snippets are runnable and which are illustrative. Two caveats: the accompanying "lint fix" enables only two ESLint rules while dropping all Next.js rules and adding an unused dependency, and the one genuinely interesting Next.js decision — turning `next/headers` into a dynamic import so the service can be tested outside Next — is never explained anywhere in the course.
