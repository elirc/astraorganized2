## What Astra did well
- **The security fix is the most consequential in B12 and it is done properly.** The snapshot `astraupskill/snapshots/src__lib__auth__session.ts.original` shows `encodeSession`/`decodeSession` doing `Buffer.from(JSON.stringify({userId})).toString("base64url")` — an unauthenticated, unsigned, client-readable identity claim. Any user could set `portal_session` to `btoa('{"userId":"user_admin"}')` and become an admin. The replacement stores `sessions: Map<string, {userId, expiresAt}>` server-side, sets only a `crypto.randomUUID()` in an `HttpOnly`, `SameSite=Lax`, production-`Secure` cookie, rejects missing/unknown/expired handles, deletes the entry on logout, and resolves the user afresh on every request so role changes and revocation are observable.
- **The aggregation fix is the right shape.** `src/modules/dashboard/service.ts` now computes `allowedClientIds` → `allowedProjectIds` → filtered `clients/projects/invoices/proposals`, and only then counts and reduces. The course names the principle precisely (in the file currently labelled `01-CODEBASE-MAP.md`): "Aggregation follows authorization… explain why filtering after summing is too late."
- **Token-out-of-the-response is a real, frequently-missed detail with a real test.** `src/modules/auth/service.ts` now returns `{ user: session.user }` with the comment "The opaque token stays in the HttpOnly cookie. Never serialize it into the login response where browser JavaScript could read it as a bearer token." `tests/integration/auth-login-route.test.ts` builds an actual `Request`, calls `POST` directly, and asserts the body. That is a route regression, not a mock assertion.
- **The trace-lab numbers are exact.** The chapter currently in `06-SOLUTIONS-AND-REVIEW.md` claims: client `user_client` (Morgan Vale) sees `client_northstar` → `project_ops_portal`, outstanding `420000`, paid `0`, time `0`; admin additionally picks up the foreign paid invoice `240000` and time `300` billable / `90` non-billable. I checked all of these against `src/lib/demo/state.ts` (`balanceInCents: 420000`, `totalInCents: 240000`, `minutes: 180 + 120` billable, `minutes: 90` non-billable) and against `tests/integration/dashboard-overview.test.ts:16-19,28,49`. Every figure matches.
- **The limits chapter is genuinely good.** The file currently labelled `07-TRACE-LAB.md` states that the session map is process-local, that a restart invalidates every handle, that two instances do not share revocation state, that demo passwords are plaintext fixtures, and that client time totals are redacted by design — and then sets an exercise to "propose a restart-safe session repository and list its new tests without claiming that the current process map provides durability."

## One-paragraph summary for the index
The code change here is excellent and the course wrapped around it is structurally broken. Astra found and fixed a textbook authentication hole — the session cookie was `base64url(JSON.stringify({userId}))`, so any user could edit it to become an admin — and replaced it with an opaque `crypto.randomUUID()` handle bound server-side to a user id and expiry, with real logout revocation and fresh user resolution on every request. It also stopped the login route from serializing that handle into its JSON body (with an actual route regression that POSTs a real `Request`), scoped the dashboard aggregate to the actor's client memberships *before* counting instead of after, and made the permission table fail closed on unknown roles. Fifteen real tests cover forged handles, expiry, logout replay, role re-resolution, admin vs client vs foreign totals and unknown-role denial, and the trace-lab figures I checked (420000 outstanding, 240000 paid, 300/90 minutes) are exactly right. But seven of the nine chapter files contain the content of the *next* chapter — `01-CODEBASE-MAP.md` holds the concepts, `02-CONCEPTS.md` holds the worked change, `06-SOLUTIONS-AND-REVIEW.md` holds the trace lab — so the reading order the README prescribes delivers material out of sequence; `VERIFICATION.md` claims twelve tests when there are fifteen; the same three-link "Sources" block is pasted into all nine files; and there is not a single code block anywhere. Read `src/lib/auth/session.ts` against `astraupskill/snapshots/src__lib__auth__session.ts.original` — that diff alone is worth an hour — and treat the chapters as unordered notes until they are re-filed.
